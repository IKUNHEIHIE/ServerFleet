### InvalidCheck不能单维度推出HTTP400

本基线的链路为：InventorySource提供坏ID → [ReadVisibleInventory](../../../../internal/nodes/read_usecase.go#L61-L77)调用同次scope.CheckNode → [CheckNode](../../../../internal/auth/node_read_scope.go#L80-L102)返回固定InvalidCheck → 用例返回nil/该错误。它没有接收一个HTTP nodeId参数。相同sentinel还用于预检的subject/context输入错误，所以单看errors.Is(err, auth.ErrInvalidCheck)不能知道错误是客户端参数、可信绑定错误还是后台数据故障。

**事实**是目前信息不足且无HTTP mapper；**推断/未来验收要求**是适配层须能审查失败阶段与来源，制定脱敏公开映射，再分别验证两种成因。本文不加错误包装、来源端口或具体响应码；这项仍归D06，而不是将已有schema中的400宣称为实现依据。

## 交给总体方案的安全证据依赖

以下是现有OPEN事项的证据要求，不是新增产品选项；由READ-PLAN-01统一整理实施依赖和负责人选择，随后交安全/契约/总控审查。

1. **来源与权限适用性可追溯**：S01–S09的层级、缺失ADR的适用条款及补证责任明确；不将引用或候选升格为批准，不把AI/Agent特定控制错用为Web协议选择。对应A01–A04。
2. **D05决定与可信数据流明确**：最终身份/凭据和撤销边界获批，来源当前性及身份→策略→用例的绑定可审核；没有客户端自报授权/匿名默认放行。对应A01–A03、A10–A12。
3. **D06有成因与兼容证据**：旧Bearer列表/新详情、Error/Problem差异及防枚举/取消等表现经审查；坏后端ID与坏客户端输入分开验证，不直接InvalidCheck→400。对应A05–A09。
4. **D07承诺与窗口明确**：空库存预检、共同范围、来源失败/部分列表、授权后字段/计数、请求生命周期及撤权/输出边界均有针对真实组合的证据；不能以再读一次或离线PASS替代原子性证明。对应A08、A10–A14。
5. **缓存/来源切换与负向记录齐全**：按最终批准设计检查服务端到浏览器全链路隔离，所用Web交付先获接收；本地schema、组件最终DOM或合成key不能替代真实主体切换验收。对应A07、A15–A16。

此处“真实验收”全部是未来验证方法，未在本轮执行。未实现项标PENDING，未运行项保留UNTESTED；本轮没有编造运行FAIL/PASS，没有关闭D05/D06/D07、P1-C10或宣布G2冻结。
