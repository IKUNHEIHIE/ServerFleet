# 备份自动异地上传、保留清理与人工处置（R29）

这份说明对应正式代码。真实存储供应商和用户节点的联调由用户进行；合成 TLS、SQLite 与 Web 测试不等于生产恢复验收。

## 配置与使用

1. 按既有 [PRODUCT-STARTUP](PRODUCT-STARTUP.md) 配置主控的加密备份部署，保留 age 接收方、公钥指纹及离线恢复密钥流程。在备份页生成密钥确认文件，离线解密验证后提交公开证明。在线主控不接受恢复私钥。
2. 系统设置 → 安全凭据，新增“备份存储秘密”，允许模块填 `backups`。S3 的秘密值是紧凑 JSON `{"accessKeyId":"YOUR_ID","secretAccessKey":"YOUR_SECRET"}`，临时凭据可增加 `sessionToken`；WebDAV 是 `{"username":"YOUR_USER","password":"YOUR_PASSWORD"}`。秘密进入现有加密凭据仓库；策略、任务和页面只保存引用及当前修订。不要把秘密写入对象 URL、证据、任务参数或日志。
3. 备份与恢复 → 打开备份维护。选择 S3 或 WebDAV、公网 HTTPS 端点、前缀和凭据。S3 额外填写 bucket 与 region，使用 path-style 通用 bucket。WebDAV 填写已经存在的目录，前缀下目录也需预先创建；系统不会运行 MKCOL 或扫描目录。
4. 保存策略后，可以启用定时加密备份（1–168 小时）和自动上传。保存者是策略的执行身份；被撤销管理员权限、凭据轮换／过期或策略修订变化，会停止旧任务继续借用凭据。轮换凭据后重新保存策略绑定新修订。
5. 手动“上传异地”或自动任务均先持久化意图，再条件 PUT（If-None-Match: *），随后完整 GET 密文并校验长度与 SHA256。只有统一任务完成的 verified 回执才参与自动清理保护。上传超时／中断／重启为 UNKNOWN，绝不自行重复 PUT。用“只读核验异地副本”创建新任务观察原对象；原上传任务仍为 UNKNOWN。

S3 需要对指定 bucket/prefix 的 PutObject、GetObject、DeleteObject 权限；启用版本管理时还需相应 GetObjectVersion／DeleteObjectVersion 权限。无 ListBucket、建桶、ACL 或公开对象需求。存储供应商必须遵守条件写入、ETag 条件删除、准确版本读取及删除后的读取语义；不兼容或无强 ETag 时保留副本，清理拒绝／UNKNOWN。对象锁、保留锁或供应商拒绝也不会被绕过。TLS 只信任系统 CA，最低 TLS1.3；本版不支持私有网段端点、自定义 CA、代理、重定向或 SigV4 非标准供应商。网络请求不会自动重试。备份维护任务与备份凭据借用最长 10 分钟，其他模块保留原 30 秒借用期限；调用者更短期限优先，取消或撤权会中断传输。

对象键绑定主控权威、备份 ID 与完整密文摘要；只管理自身持久回执中的对象。更换存储位置不会批量删除旧位置。若需要核验旧位置，将策略显式配置回相同端点/bucket/prefix 并绑定当前凭据；位置摘要不含凭据修订，因此支持密钥轮换。上传记录保留 ETag 和 S3 versionId，清理只删该确切版本，不扫描或清空整个 bucket，也不声称清理所有历史版本或费用。

## 保留与清理

本地／异地分别配置天数（1–3650）和最少份数（1–1000），默认本地 7 天至少 3 份、异地 30 天至少 7 份。同一接收方的有效副本分别排序；异地还按目标位置区分。天数内或最少份数内均保留。本地最少份数对应的保留副本会校验真实文件与摘要；缺失／损坏的元数据不凑数。删除异地副本前，在已审批任务中重新读回足够数量、同接收方且更新的异地副本，确认真实保留底线。原加密任务未明确完成、远端核验任务未明确完成、本地 deleting／unknown、上传／删除 UNKNOWN、标为保留、活动下载中的密文都不自动清理；未知明文暂存区继续隔离。

“预览保留清理”冻结最多 100 个候选及保护原因，绑定当前策略修订和 24 小时期限。勾选核对后创建清理任务，再由另一位管理员在任务详情批准。可启用“自动发起清理审批”，每天自动创建有候选的审批任务，实际删除仍遵守统一独立审批、修改类并发和运行门；这不是无人审批删除。

执行时逐项复核，不再符合条件就跳过。本地删除默认要求使用当前凭据重新读回远端密文，且同一清单不会顺手删除该保护副本。本地核对摘要和 inode，通过持久 deleting 意图、私有 tombstone、删除和 fsync 完成；最终下载登记和删除意图互斥，已有下载受保护。异地先核对完整密文和原 ETag／版本，再 If-Match 删除并 GET404 确认。任何不确定效果立即停止，记录逐项 UNKNOWN，不重放已执行清单。删除成功只改变物理副本状态，保留原备份生成事实及摘要。已完成备份残留的私有暂存目录可随清单清理；不是通用磁盘清理器。

完整维护清单最多 10000 个备份／10000 个活跃远端回执，超过则失败关闭，不能以截断清单推断最少份数。网页备份列表仍是最近 1000 条，清理记录显示最近 200 条；历史任务及原始审计保留。更大规模需后续分页／归档扩容。

## 异常／UNKNOWN 的统一人工处置

任务中心及任务详情 → 打开人工处置。后台按分钟收集统一任务的 unknown、failed、partial_failure、expired，以及 AI Agent 的 unknown、failed、limit_reached；“收集最新异常”仅登记事实，不执行或重试。收件箱显示最近 1000 条当前有权读取的记录，详情再次校验原来源修订和当前权限。AI 只暴露操作标识与终态，私人目标、聊天、工具输出和模型推理不进入收件箱。

- **认领与核验**：认领记录，检查资源实际状态、原任务的逐节点回执和日志，附上证据说明／外部证据引用。备份上传可先运行上述只读核验，其他功能使用其已有受控核验入口。可记录补充证据，释放认领或说明原因后接管；接管会撤回旧提案，重新核查。
- **后续任务**：需要补偿或重做时，通过对应功能创建新的明确任务，记录其 ID 后关联；新任务必须晚于本处置记录创建，且调用者有权读取。关联不会借用原审批，也不会批准或运行任务。不得盲目复制 UNKNOWN 的副作用操作。
- **提出人工结论**：负责人选择人工确认已生效／失败／未生效／接受仍未查明，填写依据。状态进入待复核。
- **独立复核**：另一位当前管理员核验并批准／驳回；提出者也必须仍有管理员权限。批准为“已人工结案”，原 task／AI run 的 UNKNOWN 或失败结果仍保留。驳回返回核查；结案后可以重新打开。一个管理员无法自我完成独立复核，应增设独立管理员。

所有修改需 note、expectedRevision、requestId；同 requestId+相同输入幂等，冲突拒绝。网络结果未确认时先刷新核对，不换请求编号盲目重发。记录保存不可覆盖的事件序列、提出者、复核者和关联任务；每条最多 200 个事件、20 个关联，达到边界拒绝继续写入，保留既有证据。证据写入和读取都经过秘密过滤，Root／恢复私钥和预签名 URL 拒绝；证据不应包含任何真实秘密。

离线恢复使自动备份／上传／清理策略停用并增加修订，使旧人工结论失效重开，清除当前认领／提案和执行关联，保留过去证据及恢复日志，并增加单独的恢复次数／时间标记；事件已满也不会阻断离线恢复。需要由当前管理员重新配置并核验；不会恢复旧会话、审批或 UNKNOWN 执行权。

## 权限与验证边界

新增两个追加迁移，完整 Controller 为 42 个。没有新增第三方 Go/npm 依赖。前端只访问 Controller REST；上传、核验、删除均走统一 Controller 任务，凭据服务绑定模块／当前 task／plan／source／revision 的私有借用租约，每次网络请求和流式读取重检当前权限。SSRF 过滤覆盖私有／环回／链路／元数据／映射／转换地址，DNS 解析后逐一校验并按已校验 IP 直连；禁止代理与跳转。真实供应商兼容性、凭据权限、备份离线解密和恢复演练由部署者联调。
