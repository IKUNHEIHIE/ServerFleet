## 目标与候选内部接缝

针对r03 D07已复现的空库存不读策略、每节点可读到不同策略的限制，新增一个**不需要先有目标节点**的离线读取准备入口。它先验证可信调用方明确传入的主体、读取并校验本轮策略、生成字段私有的不可变读取范围，之后才供未来读取服务选择节点。

可用最小形状表达为PrepareNodeReadScope(ctx, subjectID, PolicyReader)及返回范围的CheckNode(ctx, nodeID)；具体局部命名可调整，但不能实现或替换现有Authorizer，不新增公开HTTP合同或修改当前实时NodePolicyAuthorizer行为。返回对象不是身份/授权票据，不接生产组合根或全局缓存。

## 必须成立的规则

1. 主体必须由未来可信认证适配绑定，不能因客户端自报SubjectID就信任。策略来源必须显式PolicyReader；nil读取器、nil策略、坏配置/悬空授权和读取失败均失败关闭。空/非法主体、未知主体、取消/期限的错误分类沿用auth既有语义，错误不回显读取器异常/主体/节点/策略内容。
2. **没有库存节点也能先做预检**；不能构造假节点ID调用现有EvaluateNodePolicy来绕过空目标保护。已知主体无授权可以形成有效但零资源的范围，任何实际CheckNode都拒绝；未知主体不能因为列表为空就成功。
3. 每次准备只读取一次当前策略，并校验来源；结果不持有可变原map/slice、读取器或旧范围兜底。返回对象的所有成员集合都私有；如有集合访问器只能给副本。输入在创建期间须按PolicyReader约定保持不可变，创建后来源map被替换/修改不能改变已捕获的范围。
4. 范围只表达nodes.read精确节点读取，不接受通配、空目标、其他主体/动作、管理员特例、AI/root/插件权限。零值/nil范围不能作为有效预检或默认放行。通过准备或CheckNode都不证明登录、审批或执行许可。
5. 新的一次准备必须重新读取策略，撤权后新范围拒绝被移除节点；没有跨请求授权缓存。旧范围只是显式时点快照，不能用它宣称捕获后的撤权已被即时发现或与序列化原子绑定；不得跨请求复用为当前权限。
6. 取消/期限入口及读取后检查，复制/返回期间同样不得把取消变成允许；包装context错误保留errors.Is分类，避免回显包装文字。来源需配合ctx，不创建后台goroutine强杀不合作的读取器。

## 验收

直接测试新增实现：无库存前提下已知主体/未知主体/空主体/有效零授权、nil/错误/坏策略；每次准备恰好一次读取；来源map及返回集合修改隔离；捕获后来源变化不改旧快照、新准备看到撤权；零值/nil范围/坏节点/通配拒绝；调用前及最后读取内取消/期限；读取器敏感错误不输出。保留原授权测试全部通过，不能为了新范围放松Check的空目标拒绝。
