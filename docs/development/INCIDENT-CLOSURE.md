# 异常／UNKNOWN 人工处置闭环（R30）

入口：任务中心或任务详情的「异常与 UNKNOWN 人工处置」。当前人类管理员通过 HTTPS 登录，且须具有来源及关联任务的当前资源读取权限；管理员身份不替代节点授权。任务与 AI 的异常由每分钟收集器或「收集最新异常」纳入。按执行标识去重，来源修订增加不会产生同一执行的新处置；旧重复记录保留。

## 完成一次处置

1. 筛选待处置记录并「认领处置」。查看原始观察、当前来源状态和任务逐目标回执。AI 只提供运行标识、状态和任务引用，不把私人聊天复制到处置页。
2. 负责人登记三类结构化证据：实际资源状态、执行日志与痕迹、影响与补偿核对。每类填写核验时间、可追溯引用和说明，核验时间必须在最近24小时内且不晚于当前时间。引用是记录号或安全地址，不自动抓取；不粘贴密码、Token、私钥、带凭据／签名的链接或完整秘密输出。说明备注不能替代这三类证据。
3. 需要诊断、补偿或修复时，在原有业务入口新建统一任务，再在此关联其 ID。须为本处置创建后产生的不同任务，且在原资源范围内；节点目标须为原范围子集，Controller 任务须同资源与业务域。关联不赋予任何审批或执行权限，不重跑原 UNKNOWN。任务详情仍是完整执行结果入口。
4. 等待后续任务结束，点击「生成最新核验快照」。服务端重新读取来源、逐目标结果汇总、后续任务和本轮证据，留存不可覆盖的快照。快照有效期15分钟；新证据、关联任务或事实变化后需重新生成。
5. 核对三项确认，选择人工结论并写明理由，提交待复核。负责人和复核人都必须基于同一个当前快照。页面中的确认随快照／提案变化失效。
6. 另一名当前管理员查看证据台账、当前结果和提案，明确勾选独立核验，再复核通过或驳回。不得自己复核自己的提案；提案人也必须仍具有管理员资格。通过后记录人工结案时间、结论和复核人。

| 人工结论 | 后端准入条件 |
| --- | --- |
| 确认已生效／确认未生效 | 三类新鲜证据和当前快照；所有后续任务已完成且无失败、超时、未知或未完成目标 |
| 确认失败 | 三类新鲜证据和当前快照；后续任务均已终结且无未知／未完成目标，允许有已知失败 |
| 接受尚未查明的结果 | 后续任务仍须全部终结且可读取；额外登记24小时内的风险控制证据，明确接受未知风险并填写剩余风险和理由 |

所有结论均为人工认定。原任务／AI 的 UNKNOWN、失败或逐目标结果始终保留，处置不会将其改成机器成功。即使没有后续任务，三类证据和独立复核仍是必需项。

## 备份上传异常的只读核验

对于 `backups.upload` 来源，负责人可直接「创建并关联备份只读核验任务」。服务端选择该次上传的远端记录，经现有备份权限、凭据修订和统一任务通道提交 `backups.remote.verify`；只读回校验，不重新上传或清理对象。此路径仅允许关联该次上传记录的核验任务，不能关联另一份成功备份来证明当前上传成功。

202响应只表示任务已准入。查看返回任务的实际结果，再登记证据并生成新快照。若响应提示「关联发生冲突」，已准入的任务 ID 仍显示在页面：保存这个 ID，刷新处置后用「关联新建的后续任务」关联；不要再次创建任务。网络响应未知时复用相同请求，不盲目重复发起。重复请求若因处置修订变化而冲突，应先刷新并查看已关联任务／任务中心。

## 新事实、接管和恢复

提案和复核都在处置写事务中再次检查当前事实，避免用旧页面确认新结果。任务待审批、排队、运行或当前不可读会阻止所有结案；后续任务变为 UNKNOWN 时只能走明确的风险接受路径。单纯勾选页面确认不能绕过服务端检查。

已结案或待复核记录出现来源／后续任务／证据事实变化时，读取立即显示「待重新核查」，后台轮转扫描会清除当前提案、开始新证据轮次并重新打开调查。旧结论和快照保留在历史中；仅证据随时间变老不会反复打开已结案记录。释放、接管、主动重新打开和离线恢复也会使当前轮次失效，旧证据不删除；负责人须重新登记证据、生成快照和提案。恢复不会继承执行权或自动重放任务。

证据台账显示所有轮次，当前权限撤销后任务快照会遮蔽为不可用，不能借历史快照继续读取已撤权任务。来源本身不可读时整个处置不可读。

## 边界与验证范围

列表默认待处置，每页50条、最多100条；按状态、来源类型和原任务筛选，游标绑定身份与筛选。服务端每次最多扫描1000候选；空页有下一页时可继续。证据每页50条，向后翻页。每条处置最多200个历史动作／请求绑定和20个后续任务；达到边界拒绝继续写入，不截断旧证据。后台每分钟最多轮转100条待复核／已结案记录，记录较多时自动重新打开会延迟；详情的实时评估和结案阻断不等待扫描。日志满时无法追加自动重新打开事件，详情仍提示需要重新核查，不应将旧结论用于新事实。

只追加 `cx/0023_incident_closure_evidence`，Controller组合迁移共43项；旧SQL、checksum及历史升级样本保持。旧R29提案缺少快照／检查，不允许直接通过，可由原负责人补证据并重新提案或接管后重做。

本轮测试覆盖 SQLite 证据不可篡改摘要、CAS／幂等、独立复核、事实变化／过期／恢复、真实 HTTPS Controller 路由及正式 React 组件。Controller用例使用合成持久任务结果，页面用例使用明确的测试HTTP响应；这些结果不代表真实 Agent、生产异常、远端存储或真实模型联调已验收。真实环境验证仍由用户进行。
