# 持续监控、主机流量与通知投递

R32 / V09-CLOUD-MONITOR-ALERT-01 / chatgpt-monitor-20261111。基于已接收 main `7cc452d13915de35548d7f42315a2421bba8765b`；R31 的 PR #22 已合入，本轮变更另行检查、审查与接收，不把历史 CI 当成本轮证据。

## 配置与使用

1. 在系统设置 → 安全凭据中创建 SMTP 密码（用途 smtp）或 QQ Bot Secret（用途 qqbot）。秘密由现有凭据服务加密保存。通知渠道仅选择凭据 ID，不输入密码或 AppSecret。
2. 进入通知渠道，保存服务器／收件人或 QQ AppID／OpenID，再绑定当前凭据。绑定记录保存者、凭据修订和完整公开配置摘要；修改渠道、轮换或撤销凭据后重新绑定。页面显示后台授权状态。SMTP 仅 TLS／STARTTLS，QQ 主动消息仍受官方权限、主动推送额度及 OpenID 约束。
3. 测试消息先创建统一任务。排队、已提交、平台已接受、失败和投递未知分别显示；平台接受不代表已读。投递记录和监控告警历史均可打开真实任务。UNKNOWN 从任务中心进入已有人工处置流程，不自动重发。
4. 新建／编辑服务监控，选择连续失败／恢复次数及通知渠道。当前探测源是 Controller；非空 sourceNodeId 明确拒绝，不伪装成远程 Agent 探测。目标仍经过白名单、DNS／重定向与 SSRF 校验。显式空通知列表不发告警；保留的旧空值配置使用自动首选渠道。选择 SMTP 和 QQ 会分别产生一条告警与任务，显式渠道不再追加 SMTP 备用；自动渠道或手动 QQ 测试可按策略单独创建备用任务。
5. 在节点流量配额中保存每月重置日（1—28）、IANA 时区、入站／出站／合计、升序阈值、到期时间和降序提醒天数。空提醒天数延用 7 天提醒。一次跨越多个阈值只提醒当前最高档，后续更高档独立提醒；到期提醒按节点、实际到期时间和提醒天数去重，不跨周期重复同一到期事件。配额仅提醒，不停机、断网、续费或购买。

## 运行与持久化

正式 provision 已生成的 ControllerAuthorityID 启用统一投递执行及三个后台循环：监控每 10 秒扫描最多 50 项，轮转防止后排饥饿；配额每 30 秒扫描；未绑定投递与终态回收每 5 秒处理。每轮有独立超时，关闭 Controller 会取消并等待自有循环。监控／配额清单上限为 1000 项，超限明确报错，不静默截取。旧的未配置 authority 装配不偷偷启用外发循环。

监控配置保存当前所有者与修订；探测前后核验当前权限，写入通过配置修订与观察修订 CAS。探测采样、状态与告警 outbox 在同一事务提交。连续阈值实际生效；一次未达到阈值的失败不宣称已经宕机。维护／暂停抑制后台告警。通知失败不会把已经完成的手动探测谎报成“未执行”；未发送事件仍在历史中显示等待渠道。

通知只有 `notifications.send` Controller 标准任务能进入实际发送。任务参数只含 deliveryId、attempt、intentSha256；收件配置、正文和凭据引用冻结在专用私有意图中。发送前同一事务保存 submitted / attempt_pending、尝试次数与审计。凭据借用只在进程内真实 worker 上下文中开放，按实际任务计划、管理员、模块及当前凭据修订校验；SMTP 各阶段、QQ 两次请求前后再次核验。取消、失权、配置变化和凭据撤销不能借由排队旧任务继续外发。结果提交／凭据审计中断归为未知，不自动重发。

持久告警 claim 不受手动测试的短期去重窗口影响。提交任务与绑定意图之间崩溃可按同一确定键恢复；开始发送的 fence 不能再次使用。已确认未开始发送的取消／失败可由管理员在退避和重试上限内明确重试，新尝试保留原正文和来源修订。UNKNOWN、接受、已提交及拒绝结果不提供普通重试。QQ 确定失败的备用 SMTP 是单独冻结、单独授权和去重的任务，UNKNOWN 与限流不触发备用。原任务 UNKNOWN 保留，沿用 R30 人工结案证据，不能用人工结案冒充供应商实际接受。

旧监控／配额无保存者授权，迁移后需重新保存才进行背景操作；旧渠道须重新绑定真实凭据。旧遗留 queued 无执行证据的投递迁移为 delivery_unknown / legacy_unfinished，不猜测已发送或自动重试。新增 ds/0084、0085、0086 后共 48 项迁移，旧 SQL／checksum／历史夹具不改写。

## 流量数据含义

Linux Agent 读取 `/proc/net/dev`，统计所有非 lo 接口的 RX／TX 计数，附排序后的接口集合摘要，经已有 Protobuf MetricPoint 和已认证 mTLS 上报。旧 Agent 无新指标仍可接入；不可读取／解析时不捏造零。接口包含虚拟网卡，因此可能重复统计转发流量，这始终是主机估算而非云账单。

Controller 持久保存节点 boot ID、接口摘要、观察时间、计数基线、周期累计和采样覆盖。首次采样不产生已用流量；第二次连续采样只累计可见增量。重复／乱序不增加；重启、接口变化、计数下降、超过 5 分钟缺口或跨账期建立新基线，不补算中断或安装前流量。页面展示覆盖起止、采样数和缺口数，主机估算不声明全周期完整。

历史样本最多每 5 分钟写一项，自动清理超过 35 天的主机样本；周期累计和覆盖仍保存。当前周期存在供应商账单／人工修正时不以主机估算覆盖；本轮没有新增云厂商账单抓取接口。无使用量仍可发独立到期提醒，正文明确“无当前测量”，不会写“已用 0”。
