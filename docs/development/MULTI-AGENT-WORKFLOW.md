# 开发协作与任务交接

先读 [HANDOFF](HANDOFF.md)。本指南适用于现有正式源码；旧三平台/P1 Mock 工作包仅为历史，不给当前 Agent 固定模型或写权限。未明确请求时不自动启动其他 Agent。

## 任务记录

每个任务记录：任务 ID、唯一会话 ID、目标、允许目录、公共契约/共享文件影响、输入基线、验证、停止条件和交付 PR。可以从当前请求推导常规细节，不为已授权实现反复确认。当前任务例：R40 / docs-handoff-20261114，仅现行 Markdown/AGENTS，停止于审查和正常合并，不改运行代码或生产环境。

并行时一个任务一个分支/Worktree；模型名称不是唯一会话 ID。集成负责人协调契约、锁、生成、迁移、依赖/CI；作者提交具体兼容差异，不通过宽泛目录授权覆盖其他任务。

## 实施与集成

1. 核对远程 main、本地变更和当前状态，建立任务分支。
2. 在授权范围实现，变更 UI/功能/接口时同步现行说明；原始资料和历史证据不改写。
3. 按影响验证，记录最终 head 的结果；纯文档不跑完整 CI。
4. 通过 PR 审查差异和来源，负责人按 expected head 正常合并；不直接推 main、强推或自我 APPROVE。
5. 更新当前状态/任务板和交付链接；未验收/未装配明确保留。

不要通过本地 integration→main 快进绕过远程 PR。旧会话的 awskr/VPS/真实账号权限不继承；没有实际执行回报不写 IN PROGRESS，准备完成不等于已验收。CI 结果补评论，需轮询则十分钟一次。
