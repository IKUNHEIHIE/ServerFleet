# 多 Agent 协作流程（项目负责人版）

开始多会话之前，先明确批准下一批任务。P1 交付不会自动启动任何 Agent。建议第一批同时最多 3 个独立任务：Codex 做候选接口评审，DeepSeek 做独立领域 Mock，Gemini 做 Mock UI。涉及真实授权/任务/通信联调的工作须等 G2 核心评审和必需安全证据。

1. **挑任务**：从 FIRST-BATCH-WORK-PACKAGES 选任务编号；让集成负责人在 TASK-BOARD 填执行会话 ID、允许目录、审查人、基础提交和停止条件。
2. **准备工作目录**：集成负责人在干净 main 上用 Worktree 脚本为任务创建分支和目录。依赖安装/本地工具分别放在该 Worktree，不共享写入 node_modules 或数据库。
3. **交给会话**：打开对应目录的新会话，粘贴下面任务单。会话只能改任务目录，发现需要公共文件时提出具体差异并继续可独立的工作，不抢改共享文件。
4. **完成自检**：执行人按模块测试，加至少一个失败/越权用例，提交独立变更；写明实际命令和未验证项，停止等待审查，不自行合并。
5. **集中审查**：集成负责人检查 diff、模块边界、接口兼容性、生成代码/合同同步、秘密与执行旁路。安全/公共接口由对应 owner 共同审查。
6. **集成验证**：简单独立提交在临时 integration 分支合并；多个依赖变更按接口→实现→调用方顺序。冲突只由相关 owner 协调，解决后重新跑受影响检查和全量基础检查。
7. **合并并清理**：只有集成负责人把审查通过的 integration 结果合入 main；保留提交记录、验收证据和任务状态。确认已合并、干净且无需要保留的忽略文件后移除 Worktree。

## 分支与提交

| 分支 | 用途 |
|---|---|
| `main` | 审查后稳定基线，普通会话不可直接写入 |
| `feature/<任务>-<会话>` | 独立实现 |
| `fix/<任务>-<会话>` | 单一修复 |
| `contract/<任务>-<会话>` | 公共接口候选修订，必须兼容性说明 |
| `integration/<批次>` | 集成负责人组合多个已审查任务 |
| `docs/...`、`chore/...` | 独立文档或工具维护 |

使用小写英文、数字和连字符；提交/PR 标题 `feat(nodes): ...`、`fix(auth): ...` 等。CI 校验 PR 分支、标题与 PR 范围内非合并提交标题；本地校验当前分支和最近一次提交。没有远程时，只使用本地 diff/分支审查，不声称已建 PR。

## 交给任意 Agent 的任务单

```text
项目：Server Fleet；任务 ID：待填；执行会话：待填
基础提交：待填；分支：待填；Worktree 绝对路径：待填
允许修改：待填；禁止修改：所有共享文件及其他任务目录
先读根 AGENTS.md、模块归属、依赖规则和该目录 AGENTS.md。
本任务目标与自动验收：待填；依赖的候选接口：待填，G2 未冻结。
审查人：待填；只在任务范围内实现；不得连接真实节点或改安全 ADR。
完成后提交本地变更，提供测试证据、失败/未验证项，立即停止并等待审查。
```

紧急修复也不得强推、硬重置、覆盖其他会话或自行更改公共契约。若两个任务意外修改同一文件，暂停相关写入，负责人决定拆分或按顺序集成；禁止让两个会话互相覆盖“最终版”。
