# 指定节点的服务监控

R33 / V09-CLOUD-NODE-PROBES-01 / chatgpt-node-probes-20261111。从已接收 R32 main bc0d552 接续；源码、Web 与独立 API 候选一起交付，最终接收以本轮 PR 合并状态和精确 head CI 评论为准，不用旧 CI 替代。

## 使用

在监控告警 → 服务监控创建／编辑条目，选择 Controller 或已有节点作为“探测来源”。节点模式支持 HTTP/HTTPS、TCP、TLS；保存失败／恢复次数与通知渠道后，后台从该节点执行检查，列表与检查历史可打开实际探测任务。暂停／恢复保留所选来源。Controller 原有白名单与内部 CA 配置不变。

需要在用户资源授权中，给执行者显式授予该源节点的 `monitoring.probe` 权限，并具有监控管理权限。节点列表与任务详情分别仍需原有 nodes.read 和 tasks.read 权限。管理员也没有隐式节点授权；升级系统不会自动扩张旧资源授权。后台用配置保存者的当前权限；手动探测额外核对点击者自己的节点权限，不借用保存者的资源范围。

源 Agent 必须更新到包含 monitoring.probe 能力的版本；能力通过既有 mTLS 握手协商，不另开端口。无需 Shell、root、SSH 或外部探测平台。

节点侧首版采用固定的公网探测策略：HTTP URL 或 TCP/TLS host:port，目标最长1024字节，目标超时1—30秒。拒绝 userinfo、metadata、localhost、私网、链路本地、CGNAT 等目标，解析后的地址和每次重定向都重新校验；不接受自定义方法、认证头、正文、代理、CA 或私网白名单。需要明确私网／内部信任覆盖的检查可继续选择已配置的 Controller 源。TLS 检查使用 Agent 的系统信任，不跳过证书验证。

## 状态与任务

- 只有当前统一任务完成且收到匹配的类型化回执，才把节点探测结果认定为 up 或 down。HTTP 5xx、连接失败、TLS失败等实际目标检查失败，按连续失败阈值累计。
- 源节点离线、能力不支持、权限变化、排队超时、执行取消／UNKNOWN、回执缺失或源策略拒绝，产生 unknown 观察；不会当成业务宕机或恢复，也不会发送虚假的业务状态变更通知。
- unknown 会打断“连续”失败／恢复计数。内部保留最后一个确定的业务状态用于后续正确的 down/recovered 变更判断，但页面当前状态明确显示未知。来源切换、目标／类型变更会清空原结论。
- 未发送任务不会等节点很久后再作为当前采样执行；每次检查有持久绝对截止时间，生产者中断会废止该私有意图，并按已有任务权限尝试取消。过期的旧回执不会被包装成当前采样。权限、配置和观察版本变化持续阻断旧任务。旧 UNKNOWN 执行不重放；后续定时采样是独立的新观察，不能改写原任务事实或自动结案其人工处置。
- 检查历史记录 sourceNodeId 和 taskId。没有实际创建任务的离线检查不伪造任务 ID、状态码、延迟或零值。HTTP200表示这次观察已记录，不等于业务正常。

## 执行边界

Agent 是固定 Go 只读探测能力，使用与 Controller 相同的纯网络校验／探测代码（internal/netprobe）；该包仅依赖标准库，不包含业务数据库、权限或任务逻辑，不是插件 Runtime。原 monitoring 导出 API 保留为兼容包装。

Controller 先持久化包含监控配置版本、观察版本、执行者、源节点、规范参数的私有运行意图，再按确定性键提交 `monitoring.probe` 标准节点任务。提交／绑定之间中断可找回原任务；任务绑定、目标、操作级别、来源及参数均核对，不能用通用任务端点绕过来源配置。Agent 沿既有 mTLS admission 在开始前、执行期间及结束时检查当前授权。目标网络超时与执行授权／回传预留时间分开，避免把普通目标超时误当成任务中断。

输出只有版本、运行键、up/down/unknown、固定原因码及可选延迟／状态码，不含响应正文或头。Controller 校验实际节点身份、任务／执行／计划摘要、当前配置和回执格式，再一次性保存；重复相同回执幂等，冲突回执拒绝，配置变化后的晚到帧不覆盖新观察。探测结果与原监控观察 CAS／告警 outbox 保持一致。
