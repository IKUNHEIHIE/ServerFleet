# 证书续签后的安装与发布

R31 在「证书 → 公网 HTTPS 证书 → 续签策略 → 安装发布编排」配置。策略必须以实际成功的签发和节点安装结果为基线。绑定最多八个已完成、使用该基线证书且域名匹配的 HTTPS 发布计划；留空则只安装并接续续签策略。

调度每十秒观察一次，每次最多轮转五十条策略，避免大批网关等待阻塞其他策略。轮次、任务 ID、计划 ID、证书集合引用和历史持久化。重启只重新观察同一确定性任务，不产生替代键重放副作用。

1. 续签签发经统一任务与独立修改审批；等待实际成功、清理完成、当前 profile/zone/CSR/节点/原基线与计划摘要匹配。
2. 使用原节点本地私钥和原 CSR 对应的真实证书公链提交安装任务。仍须独立审批与实际安装回执。私钥不离开节点。
3. 每个绑定发布创建不可变的证书替换后继。DNS 保留，原发布、域名、服务组、目标和路由身份保留。节点集合仅替换本节点对应的实际安装回执，其他节点引用保持并重新校验当前读取权限。
4. 网关配置使用原统一任务、审批、制品分发、Agent 执行、叶证书摘要和 HTTPS 健康核验。等待审批不宣称发布完成。多个节点续签串行沿已完成后继链推进；链上仍有等待操作时后续轮次等待，最多追溯 256 层。多个节点可能在签发/安装阶段同时捕获同一旧基线，因此每个发布意图在冻结证书集合前会再次跟进最新已完成后继；已有未决后继则等待。已冻结意图或已准入任务不重定向，冲突时仍停止等待人工核查。
5. 全部成功后同一事务接续策略的新签发、安装、有效期和下一轮发布 ID，保存本轮历史。只有实际成功结果可形成新基线。

权限撤销、服务组版本漂移、签发/安装证明不符、网关失败或 UNKNOWN 会停止本轮。证书替换的子计划及有替换后继的旧计划禁止通用删除补偿，避免一次轮换失败删除仍在服务的 DNS 或站点。停用编排不回滚已生效任务；已准入任务须在任务中心单独取消。

## 显式恢复

停止的周期可展开「人工修复后采用成功结果」。先独立完成成功签发、成功安装和需要修复的 HTTPS 发布。所有原关联任务必须已终止；每个 UNKNOWN 都须有同属管理员的任务人工处置单，经独立复核结案且当前事实未变化。

填写成功签发/安装 ID、修复后已完成且使用新安装证书的发布 ID、覆盖全部 UNKNOWN 的结案 ID 和依据，并人工勾选确认。默认不启用未来编排；需要继续自动化时显式勾选。提交同时校验策略和编排版本，验证新结果的当前读取权限、原节点/私钥/CSR/zone、有效期延长与成功证明，然后原子采用。修复不重试原任务，不改写 UNKNOWN，不删除原失败历史。原周期保存 recovered、原 error code、修复证明与结案引用，后续可以开始独立新周期。

人工恢复最多八个发布、六十六个结案引用；页面与接口均有边界。清空发布列表仅表示后续只安装，旧站点需独立确认，不能把未修复站点当作已完成发布。

## 存储与验证

追加 cx/0024_renewal_delivery、ds/0083_certificate_replacements，Controller 当前迁移数 45。历史 43 项 SQL、校验和和旧恢复夹具不变。新恢复后既有权威、隔离锁和当前授权门继续生效。

自动专项使用真实 SQLite 服务、真实 HTTPS/签名和 HTTP 登录/CSRF，供应商与网关端口采用明确测试夹具。真实 ACME、DNS、Nginx、跨节点和 systemd 安装需部署环境联调。详细接口和新增/修改清单见 ../contracts/revisions/v09-r31-delivery.md。
