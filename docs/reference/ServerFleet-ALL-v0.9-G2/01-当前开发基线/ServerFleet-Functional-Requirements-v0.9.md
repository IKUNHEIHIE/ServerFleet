## 1. 项目定位、导航与功能范围

### 1.1 产品定位与交付边界

Server Fleet 面向跨云、跨地区 Linux VPS 集中管理，以**轻量、集中运维、安全授权、插件按需扩展**为核心目标。产品设计包括 Controller 主控、Agent 节点、浏览器管理页面。现有 HTML 原型中的所有连接、传输、安装、审批、证书和更新流程都使用模拟状态；前端能够模拟拒绝不代表真实后端已经实现权限隔离。实际实现需依据 API 契约、已批准 ADR 和专门的负向安全测试。

“第一版功能规划”“v0.9 原型已经展示”“真实后端已实现”是三个不同概念；当前仅前两者成立。不要将原型演示状态当作上线交付状态。

### 1.3 导航与术语（FR-UI-004）

- 「节点管理」是一级**可折叠导航组**；其二级页面依次为「节点列表」「添加节点」「分组管理」。原「接入与审批」业务流程仍存在于「添加节点」，只是更名。
- 「AI 运维」属于「核心功能」，不再使用「AI 运维助手」。模型未配置时不能影响其他核心管理能力。
- 「网关管理」表示 HTTP/HTTPS **应用网关**，非系统默认路由网关；原名「服务入口管理」已废弃。
- 「DNS 管理」为跨供应商的统一产品入口；首版**仅 Cloudflare**，在系统设置中维护多个账号。
- 国家/地区图标根据可靠的地区代码生成，无法确认时显示 🌐；地区文本与国旗在节点列表、详情、网关选择器等页面保持一致。
- 「普通节点分组」（整理/筛选）与「服务组」（业务服务/调度资源）为两种独立资源，不能共用或混淆其身份与权限。

## 2. 节点管理与分组

### 2.1 节点资产、接入与状态

- 节点列表展示名称、IP、地区、云厂商、运行状态、基础资源、标签及操作；支持搜索、筛选、详情和批量选择。
- 添加节点含短期接入令牌、一键安装引导、可选人工审批、接入历史、重新安装与吊销；令牌和节点身份不可永久共用。
- 离线节点的资源指标应显示数据缺失或更新时间，不得以 `0%` 假装实时数值。
- 主控连接状态、节点身份和任务历史均应可追溯；具体 Agent 注册与信任流程遵守已批准的引导/PKI ADR。

### 2.2 分组管理（FR-NODE-GROUP-007）

**适用范围：**仅调整「节点管理 → 分组管理」交互和相关契约；其他功能与权限保持有效。

#### 2.2.1 分组语义与导航

- 一级导航维持「节点管理」，其子项仍是「节点列表 / 添加节点 / 分组管理」。
- 「自定义分组」用于管理员整理 VPS，组名、备注、成员可以编辑，同一节点可属于多个普通分组。
- 「自动分类」提供「地区 / 云厂商 / 标签」三个维度，由现有节点资产数据即时计算，**只读**、不可手动修改成员。
- 自动分类不等于真实分组资源，不得创建、重命名或删除分类值；需要修改归类信息时，应进入节点列表修改节点属性。
- **普通分组不等于服务组**：不提供网关负载均衡调度、内部证书下发或 AI 会话服务组授权。业务服务组仍使用 ServiceGroups 独立资源与接口。

#### 2.2.2 信息架构与交互

1. 顶部仅显示「自定义分组 / 自动分类」双视图切换；左侧展示当前视图下的分组或分类值，右侧始终展示节点表格。
2. 自动分类维度通过三个选项卡切换，列表显示分类计数；点击分类值直接在右侧显示节点，**不再打开自动分类弹窗**。
3. 右侧统一显示节点名、IP、地区国旗、云厂商、在线状态、CPU、内存及操作列；离线节点监控指标应显示无有效数据而非虚假 0%。
4. 右侧支持按节点名 / IP / 标签搜索以及在线状态筛选；筛选只影响当前视图，不直接修改分组成员。
5. 自定义分组详情包含「编辑分组」「管理成员」「删除分组」入口；删除分组仅删除关系，不删除节点或影响服务组调度。
6. 「管理成员」使用右侧抽屉，支持按地区、云厂商、在线状态筛选、全文搜索、单台多选、当前筛选结果全选和取消。
7. 只有点击「保存成员」才会提交完整成员集；「取消」不改变成员关系。支持从分组移除全部成员，不删除节点资源。
8. 自定义分组可跨地区、跨云厂商；允许节点属于多个普通分组。自动分类数据随节点属性变化而变化。
9. 页面在窄屏下自动将左右分栏改为纵向布局；抽屉提供明确的关闭、取消及保存操作。

#### 2.2.3 API 与权限

- `GET /api/v1/groups` 仅返回人工建立的自定义分组。
- `POST /api/v1/groups` 创建自定义分组；`GET/PATCH/DELETE /api/v1/groups/{groupId}` 读取、编辑、删除。
- `PUT /api/v1/groups/{groupId}/members` 原子替换成员集，接收 `expectedRevision` 防止并发覆盖；记录差异审计。
- `GET /api/v1/groups/classifications?dimension=region|provider|tag` 返回当前用户可见的分类和值数量。
- `GET /api/v1/groups/node-results` 统一取得人工分组或自动分类的节点结果，可搜索、按状态过滤、分页。
- 分类计数和所有节点列表均须使用当前用户的可见节点范围，不得泄露其他租户或无权限节点。
- 无论从哪个页面提交分组更新，服务端必须对全部目标 nodeId 校验当前管理权限；客户端选中不构成授权。
- 既有 AI 会话资源授权、三级审批、服务组引用、证书下发和网关调度维持原有隔离策略，不因重构自动放权。

#### 2.2.4 验收条件

- 自定义/自动视图以及地区/云厂商/标签切换无需弹窗，右侧表格内容与计数一致。
- 新建/编辑/删除自定义分组、成员全选与部分选择均可进行模拟操作；取消不提交，保存后刷新结果正确。
- 同一节点加入不同普通分组互不冲突；从普通分组移除不删除节点。
- 改动页面后原有文件互传、AI 运维、服务组、证书、DNS、插件和网关页面仍能访问。
- 真实后端必须满足权限、并发冲突和审计要求；HTML 只模拟交互，不作为后端安全验证。

## 3. 文件互传（FR-FT-001）

### 3.1 用户故事与范围

用户打开侧边栏 **核心功能 → 文件互传**，看到**左右两栏**独立文件浏览器；每栏自行选择服务器、浏览目录、搜索、上传文件、新建文件夹。用户可在任一栏勾选一个或多个项目，并发送到另一栏当前目录；任务列表显示状态及执行记录。整体结构和操作节奏参考用户给出的宝塔面板截图，不复制其品牌资产。

**原型已模拟**：左右节点切换、目录面包屑、返回上级、刷新当前目录、搜索当前目录、分页、勾选与全选、发送单项/批量、冲突策略确认、传输任务状态、取消任务、文件夹大小计算、创建文件夹、重命名、删除、上传本地文件的**元数据**、预览占位内容。

**原型尚未实现/真实产品需要**：文件字节的上传与下载、跨节点真实数据复制、可靠的断点续传、真实目录权限/配额/空间校验、传输带宽策略、文件校验、告警通知、跨页/跨目录选择。

### 3.2 页面结构

1. 两栏浏览区对等：**节点选择器 → 返回上级 → 路径面包屑 → 刷新**；第二行是 **上传文件 / 新建文件夹 / 文件名搜索**；列表包含 **复选框 / 名称 / 文件大小 / 操作**。
2. 每个项目提供 **打开（文件夹）/ 预览（文件）**、**发送到另一侧**、**更多操作（详情、重命名、删除）**。文件夹大小初始显示「计算」入口。
3. 每栏底部提供「发送到另一侧」批量按钮、选中数量及分页。未选中任何项、源/目标节点离线时禁止发送。
4. 页面下方提供统一任务列表与状态筛选：全部、进行中、已完成、失败/取消。
5. 清楚显示演示模式和模拟能力边界，不能暗示真实传输成功。

### 3.3 核心交互规则

**浏览与选择**
- 两栏彼此独立：切换其中一栏的节点或路径，不更改另一栏节点或路径；切换当前栏节点或目录时清空当前栏文件选中项和搜索条件。
- 搜索仅针对**当前目录的文件名**，不暗示递归搜索。全选仅作用于当前分页；当前选中项数独立显示。
- 文件夹进入下一级目录，面包屑可跳至任一祖先；返回上级不会越过 `/`；符号链接单独标识，当前原型不跟随和不传输。
- 文件大小按字节格式化；点击「计算」可计算演示文件夹内文件的合计体积。

**传输**
- 两侧都可作为源或目标；传输目标始终是**另一栏当前选中的服务器 + 当前目录**。
- 点击单个文件的「发送」或底部「发送」均先弹出确认框，显示源节点、源目录、目标节点、目标目录、项目数量和同名冲突处理规则。
- 同名策略：**跳过（默认）**、覆盖、自动重命名。传输是**复制**，原始文件不被自动删除。文件夹在真实系统中需明确递归复制语义。
- 源或目标节点离线，拒绝新建传输；同节点同目录复制、将文件夹复制到自身或其子目录，必须拒绝。
- 创建传输生成可查询任务；可查看进度、完成/失败/取消状态及错误信息；已开始的任务可请求取消，但可能存在已复制的部分数据，真实产品必须说明清理策略。
- 任务完成后可在目标栏刷新查看文件；应形成操作审计记录。

**文件管理操作**
- 新建文件夹：仅在当前节点当前目录创建，不允许空名称、斜杠或重名。
- 重命名：支持文件与文件夹，不应丢失文件夹的子级内容；重名及非法路径报错。
- 删除：必须二次确认；删除文件夹时显式提示对子级的影响；真实产品应由权限策略约束系统路径。
- 上传：可多选本地文件，确认后落入当前栏对应节点及路径。**演示版仅登记文件名、大小，不读取或传输真实字节**。
- 文件预览：只展示占位信息；**不应将演示预览当作实际内容**。

### 3.4 失败和边界场景

| 场景 | 期望用户反馈 |
|---|---|
| 节点离线/失去连接 | 禁止新任务并明确标记；传输中失联记失败或等待恢复（规则待定） |
| 权限不足 | 不允许列目录、下载、上传、移动或删除；返回权限错误，不泄露目录详情 |
| 目标目录不存在或路径无效 | 阻止或失败，展示具体原因 |
| 源文件在任务执行前变更 | 拒绝旧版本操作或标记该项失败，避免静默复制其他内容 |
| 文件名冲突 | 应用用户明确选择的跳过/覆盖/重命名策略 |
| 目标节点磁盘不足 | 传输失败并展示剩余空间信息（如可安全提供） |
| 部分文件成功、部分失败 | 任务提供逐项目状态；不以“全部成功”误导 |
| 传输取消 | 停止进一步复制；已落地数据如何处理为待确认事项 |
| 文件为符号链接 | 默认不跟随，防止越界；未来如支持需单独确认策略 |
| 单节点相同源目标路径 | 拒绝，避免意外覆盖 |
| 链接指向 /etc 等敏感路径 | 访问控制须检查实际访问对象，不能仅基于字符串路径授权 |

### 3.5 初步角色与审计要求

- `file.read`：查看目录和文件详情；`file.download`：下载（不等同于 read，目前原型未提供下载）。
- `file.write`：上传和新建文件夹；`file.rename`：重命名；`file.delete`：删除；`file.transfer`：跨节点复制；`transfer.cancel`：取消任务。
- 权限必须同时检查**用户、源节点、目标节点、真实路径范围和所请求操作**。尤其不能因为用户能读取源节点就假定其有权向另一节点写入。
- 创建/取消任务、文件上传、改名、删除、覆盖等需要审计：操作者、时间、节点、路径（敏感路径可以遮盖）、结果、关联任务 ID。
- 实际文件内容、凭证、私钥和密码不得直接写入审计日志。

## 4. 服务组管理（FR-SERVICEGROUP-005）

### 4.1 语义：与节点分组严格区分

- 既有 **分组管理**：标签、地区/云厂商、人工运维分类；不直接参与业务调度。
- 新增 **服务组管理**：有独立 ID 的业务资源，包含一个或多个节点、服务端口、健康检查、成员状态，可用于网关后端选择、批量任务目标、内部 TLS 凭证下发及 AI 会话资源授权。
- 同一节点允许处于多个服务组；同一服务组成员可以因离线、维护、健康检查失败或管理员暂停而被排除出**流量调度**。
- 服务组**不默认启用负载均衡**，通用资源集合（如备份、邮件系统）可以只用于统一管理。只有明确配置后端协议/端口、网关关联、调度策略和检查规则的服务组可作为流量目标。

### 4.2 基础管理能力

- 创建、编辑、删除服务组：名称、用途、成员集合、服务端口、协议/健康检查、调度启用状态、策略、关联网关。
- 服务组可批量添加/移除节点；服务成员退出调度不等于注销节点。
- 显示每个成员在线状态、健康结果、负载均衡资格、停止/恢复接收流量入口和原因。
- 只允许已完成 Nginx 安装、检查通过、在线且启用调度的网关与服务组建立可发布关系。
- 调度策略第一版建议 **轮询 / 最少连接**；不承诺跨地区无损迁移或自动扩容。
- 配置引用更新应有版本冲突保护（避免两名管理员覆盖）与完整审计。

### 4.3 与其他模块的引用

| 模块 | 服务组用法 | 特别限制 |
|---|---|---|
| 网关管理 | 路由将 `serviceGroupId` 作为后端目标，依据组内可用成员转发 | 不能绕过网关准入或服务健康检查 |
| 批量任务 | 选择服务组作为任务目标 | 提交时需要解析目标快照并校验用户权限 |
| 证书管理 | 按组批量下发信任包/身份凭证 | **逐节点独立状态**、不得共享身份私钥 |
| AI 运维 | 将服务组拖入当前对话授权资源 | **授权时冻结成员快照**；新增成员不会继承旧授权，移除成员立即失去组授权 |

**验收：** 能创建不参与负载均衡的服务组；能将服务组关联就绪网关；暂停成员后立即不参与调度；成员变更不会放大 AI 历史会话权限；删除被引用的服务组前须列出影响和处置方式。

## 5. 批量任务与服务组目标

### 5.1 基础能力

选择单台节点、多台节点或具有执行权限的服务组，输入拟执行的命令或脚本；展示目标、执行策略、状态、输出、错误、进度、任务历史和审计。危险操作必须符合用户权限与 AI 审批策略（若由 AI 发起）。前端可模拟任务，不代表真实系统命令执行。

### 5.2 服务组解析与权限规则

- 选择服务组为目标时，**提交任务即生成 `targetNodeIdsSnapshot`**，随后成员变化不得自动扩大已有任务。
- 任务提交时和执行每个目标前均应校验权限；离线、撤销权限与过期任务不得静默放行。
- 真实任务队列需要实现已批准的分批/金丝雀、失败熔断、过期保护及部分执行状态；详见 FR-0803。对任意 Shell 预演和自动回滚仍不作保证。

## 6. 网关管理（FR-GW-001；FR-GATEWAY-004）

### 6.1 模块定位与分工

- 正式将原先的「服务入口管理」一级导航及页面标题更名为 **「网关管理」**；业务定义为**应用网关**（HTTP/HTTPS 服务入口与反向代理），**不是**操作系统网络默认网关，也不表示已经具备完整通用 API 网关功能。
- 保留此前确认的部署规划：**初始规划的 4 台 Nginx 节点**统一为其他业务节点提供反向代理入口；该业务定位不改变已批准的 ADR 或初始网络拓扑。
- 网关模块提供：网关节点概览、服务路由列表、访问域名、后端服务目标、HTTPS 开关、启用/停用、创建/编辑/移除服务路由。原型仍为本地数据模拟。
- 访问域名对应的 **DNS 解析**由「DNS 管理」负责；**证书申请与生命周期**由「证书管理」负责；网关服务器的系统信息与资源监控仍由「节点管理」负责。网关界面只提供到这些模块的便捷跳转，避免出现多套冲突的配置源。

### 6.2 产品流程

`网关管理 → 新建网关 → 从在线节点中选择 → 明确授权安装或检测 → 创建安装任务 → Nginx 安装或发现 → 检查服务运行/配置有效性/必要连通性 → 就绪 → 允许调度`

- 只能选择当前在线且未作为网关登记的服务器；离线、重复节点不可选择。
- 若已安装 Nginx，应进行检测和配置审查，不应无条件覆盖已有实例或配置。
- 安装流程必须显示授权、任务状态和错误原因；安装失败允许重试但**禁止参与调度**。
- **只有**节点在线、Nginx 安装成功、服务及配置检查通过，且管理员允许调度的网关，才能进入调度候选池。
- 即使网关 `就绪`，也可进入 `维护中`；维护期间不参与调度。
- 实时离线或健康检查不通过后，调度资格应被动态收回。
- 既定 4 台 Nginx 属于**初始部署目标**，不是产品中的数量上限；未自动登记的旧计划服务器不得默认视为验证通过。
- DNS、证书与节点基础监控保持独立模块，不重复存放两套配置。

### 6.3 状态模型

| 状态 | 用户界面 | 可调度 |
|---|---|---|
| 待安装 / 安装中 | 进度及日志、取消或失败处理（具体取消行为待实现） | 否 |
| 安装失败 | 错误详情、重试 | 否 |
| 已安装但检查未通过 | 检查失败详情 | 否 |
| 就绪、在线、管理员启用 | 可展示服务路由 | **是** |
| 就绪但维护中、失联或健康检查失败 | 明确提示不可调度 | 否 |

**验收：**安装中/失败的网关不可调度，完成全部检查后可调度，进入维护立即退出调度，不能因操作失联把失败节点标记成成功。

## 7. DNS 管理与供应商（FR-DNS-001）

### 7.1 产品目标与首版范围

- 一级导航由「Cloudflare DNS」改为 **「DNS 管理」**，供应商概念从菜单名称中解耦，后续可增加其他 DNS 供应商。
- **第一版只适配 Cloudflare**。当前不开放其他供应商的创建、验证、同步及解析变更操作，也不承诺已完成接入。
- **系统设置 → DNS 供应商** 为供应商账号的统一管理入口。支持管理**多个 Cloudflare 账号**（或凭证配置），包括账号显示名称、备注、启用/停用、设为默认、删除、状态查看与连接检查。
- 「DNS 管理」页面展示**账号选择器 + 域名选择器 + 所选域名的记录表**，支持记录添加、编辑、删除和模拟同步，避免不同账号的数据混在一起。

### 7.2 用户流程

1. 打开「系统设置 → DNS 供应商」，查看当前账号、供应商类型、启用状态、是否默认和域名数量。
2. 选择「添加 Cloudflare 账号」，输入显示名称、备注并选择启用状态。**纯前端原型的 Token 输入框禁用，既不收集也不保存真实凭证**。
3. 可以编辑账号信息、启用或停用、修改默认账号，选择「模拟检查」查看预期验证项目（不会虚构验证成功）。删除账号时必须确认，且应说明其域名/记录关联会如何处理。
4. 打开「DNS 管理」，选择已启用账号，再选择该账号下的域名；页面仅展示对应的 DNS 记录。
5. 原型允许「添加演示域名」用于模拟多账号切换。**真实产品的首版域名应来自 Cloudflare 已授权 Zone 的读取和同步**，不应将这个原型按钮解释为真实的 Cloudflare 新建 Zone。
6. 管理 DNS 记录时显示记录类型、主机名、记录值、TTL、（适用时）代理标志及操作入口，保存应形成可追踪的变更记录。

### 7.3 数据和行为约束

- **账号层**：一条账号配置对应唯一 ID、供应商类型（首版仅 `cloudflare`）、显示名称、备注、启用状态、是否默认、凭证配置/验证状态（只返回状态，不返回凭证明文）。允许多个同类型供应商账号。
- **域名层**：每个 Zone 必须归属于一个具体账号；可按账号切换域名。若两个账号都可管理同一域名，仍以账号 ID + Zone ID 区分，避免误操作。
- **记录层**：必须按选定 Zone 列表和修改；禁止使用当前账号的权限修改其他账号的 Zone/记录。账号切换时切换相应的域名集合，不能继承上一账号的旧选择。
- **默认账号**：同一管理空间最多一个已启用的默认账号；停用/删除默认账号时自动选择下一个已启用账号，若无已启用账号则允许为空。默认账号只决定默认选中项，**不跨账号合并解析记录**。
- **停用账号**：停止对该账号发起新的同步/变更；不等于从 DNS 供应商删除域名。删除 Server Fleet 中的绑定不应隐式删除 Cloudflare 上的真实 Zone 或解析记录。
- **供应商能力差异**：Cloudflare 的代理开关是供应商特有能力，不作为所有供应商共有的必填字段。未来供应商适配需按能力显示字段，复用通用账号/Zone/记录流程。
- **安全**：真实 API Token 必须只在后端凭证入口提交、加密托管、可轮换/撤销、按最小范围授权，不返回原文，不写入浏览器长期存储、任务日志或审计详情。只授予所需 Zone 读取、DNS 记录编辑权限。高风险修改需根据平台授权策略审计和确认。
- **连接检查**：真实接入时分别显示凭证有效性、Zone 读取权限、DNS 写入权限、失败原因；原型仅呈现所需检查项目，不展示虚假的已连接结果。

## 8. 证书管理与内部 TLS 下发（FR-CERT-005）

### 8.1 页面划分

新增独立标签：**公网 HTTPS 证书** 与 **内部 TLS 与下发**，但统一位于「证书管理」。已有 ACME/公网证书及私有 CA 批准方案不变。

### 8.2 证书类型和目标

- **CA 信任包（trust bundle）**：可以分发同一套公开信任锚/中间证书链，**绝不**分发离线 Root CA 私钥或在线 CA 签发密钥。
- **节点/服务身份凭证（leaf certificate）**：每个成员具有独立私钥与身份，建议目标节点本地生成密钥对并生成 CSR，由受控 CA 签发；服务多实例时可扩展到工作负载级身份，不默认复用一个节点私钥。
- 下发先选服务组，显示成员数量、离线成员和证书类型；要求管理员授权后创建异步任务。
- 显示任务 ID、目标组、固定成员快照、逐节点安装状态、证书序列号/身份标识、到期时间、重试理由、失败原因、撤销/轮换状态。
- 离线节点标记为待重试，不能误计为成功；节点重装后应吊销其旧身份。
- 下发成功不等于 TLS 已建立，还须服务进程启用 TLS、验证 SAN/SPIFFE ID、信任链以及握手结果。

### 8.3 安全要求

- 各节点私钥由节点持有，主控仅传递 CSR、签发结果和受控安装任务；密钥存储权限与审计独立管控。
- 必须有证书轮换、撤销、有效期与失败重试的接口。吊销证书不代表对端立即停止信任；应记录撤销传播/信任更新状态。
- 如果组内成员变动，**原下发任务保持当时的目标快照**，新增成员必须通过新任务加入；移除或受损成员须考虑撤销其身份。
- 对已有 mTLS Agent 身份证书不得随意复用给业务服务。

**验收：** 同一组两台节点得到两个不同身份；CA 信任包与身份凭证模式可区分；离线节点显示待重试；支持查看、撤销状态与审计记录；权限不足时拒绝下发。

## 9. 监控、告警与通知（FR-NOTIFY-004）

### 9.1 基础资源监控

当前已规划对节点 CPU、内存、磁盘、网络流量等数据进行展示，支持规则设置、规则启停、异常告警和人工确认。指标时间、采集周期与失联状态必须标明；不得把过期数据展示为实时值。业务级 HTTP/HTTPS、TCP、TLS 可用性监控已在 FR-0802 批准，具体规则见第 16 章。

### 9.2 第一版包含

1. **SMTP 邮箱**：启用状态、SMTP 服务器、端口、加密方式、发件邮箱、收件邮箱、授权码/密码（仅安全写入）、测试邮件、发送日志、故障原因。
2. **QQ 官方机器人**：启用状态、机器人 AppID、AppSecret（仅安全写入）、可用通知对象类型、接收对象 ID、测试消息、发送日志、平台错误及频率限制提示。
3. **备用策略**：如果 QQ 发送失败且 SMTP 已配置和启用，可按规则尝试 SMTP；必须限制重试次数并避免消息重复、告警风暴。
4. Telegram 不属于 v1 通知渠道，原型菜单和实际可选通道中移除。

### 9.3 必须澄清的投递语义

- QQ 机器人有主动消息场景，但目标类型、授权条件和频率受平台政策限制；不能承诺“任意好友/任意群无限制主动推送”。
- 发送 API 请求成功 ≠ 收件人一定阅读；区分“平台已接受”“被拒绝/限流”“无法验证最终投递”。
- 测试按钮显示准确结果；原型仅生成“模拟发送”日志，不接入 QQ/邮件服务器，不接受真实密码。
- 通知渠道启停、测试、发送失败、备用渠道回退应有审计或诊断记录。

**验收：**两个渠道可独立配置/启停，测试时显示信息不足原因；SMTP 作为 QQ 故障备用；任何 GET/审计/普通日志不能回显密码或 AppSecret。

## 10. AI 运维：资源授权、受控工具与三级审批（FR-AI-SCOPE-005；FR-AI-APPROVAL-006）

### 10.1 前端交互

- 在 AI 运维页顶部以矩形资源块显示当前用户**有权查看**的节点和服务组。可拖入会话资源区，也可通过按钮/选择器添加，兼容触屏和无障碍操作。
- 每个聊天会话都有**独立资源授权**，默认空集合；切换/新建会话不继承先前授权。
- 授权卡片可撤回，显示资源名称、服务组成员快照数量、授权版本；添加/撤回必须产生日志。
- AI 推荐更多资源时只能给出原因、期望资源类型和所需操作权限，不能自行扩大授权；由用户的资源选择器做显式确认。

### 10.2 硬性安全边界（不能靠提示词）

令 `U` 为用户实际权限集合、`C` 为当前会话授权的资源快照、`O` 为具体工具操作权限集合：

**一次工具操作被允许 = 用户拥有该操作权限 ∧ 目标资源属于会话授权范围 ∧ 该工具/任务类型被允许。**

- 每个模型工具调用（包括读取列表、监控、日志、文件、命令、批量任务、插件调用、子 Agent 及间接执行）**必须通过服务端统一鉴权代理**；模型不可调用未经过代理的管理 API、SSH、数据库或网关控制接口。
- 即使模型在提示词中写入 `all nodes` 或伪造节点 ID，也只能在服务器端授权的有限资源集合内执行；默认拒绝、禁止 wildcard 及未经过验证的目标别名。
- 服务组授予成员的**固定快照**，对新加入节点禁止自动放权；被移除成员应立即从实际有效授权中减去。授权撤销应立即中止排队中任务，活动中任务必须尽可能安全取消或切断后续能力。
- 创建任务必须记录 `sessionId + scopeRevision + targetNodeIds + operation`；执行前以及每一阶段再次验证当前有效权限。`scopeRevision` 过期则拒绝，不能沿用旧计划。异步任务、可重试任务、插件任务同样执行此规则。
- **资源目录只读权限是独立的权限**；默认不开放 AI 检索未授权节点的名字、详情、指标、日志。推荐无授权资源时只能建议“资源类型/排查方向”，节点具体列表由管理员 UI 自行显示。
- 严格限制开放式 Shell/root、已有 SSH 私钥、凭据转发和跨节点网络访问；否则单机授权可能通过网络横向移动绕过系统级授权。
- 服务端对 AI / 用户 / Agent 身份、审计链、权限变更、拒绝原因、令牌有效期及授权回收做明确记录。客户端传入资源 ID 不构成授权凭证。

### 10.3 原型与正式安全边界

演示 HTML 的拖拽、点击、失效计划等均为**前端模拟数据**。可在 UI 演示“拒绝未授权节点”和“撤权取消旧计划”，但无法阻止开发者工具直接修改 JavaScript 状态，更无法替代真实服务端安全控制。正式验收必须使用实际后端 API 和权限负向测试。

**验收用例：**

1. 新会话零授权时请求查看所有离线节点 → 拒绝；不泄露未授权节点名称。
2. 拖入一个节点后 → 查询只返回该节点；生成更新任务也只能包含它。
3. 拖入服务组（成员 A、B）后 → 追加 C 不会扩大旧会话授权；从服务组移除 B 后 B 的有效授权被撤销。
4. AI 提议增加网关节点 → 只能展示推荐原因，必须由用户显式选择并确认，审批前 AI 无权访问该节点。
5. 创建计划后撤销授权 → 执行接口拒绝旧计划；重复提交、异步重试也不得越权。
6. 伪造调用未授权 `nodeId`、插件间接调用、开放式高权限 Shell 及跨节点凭据尝试 → 由后端拒绝并记录审计。

### 10.4 三级审批的产品目标

**产品目标：** 在 AI 运维页面设置一个独立于资源授权的「审批模式」栏，参考 Codex 的交互体验，但不复制或假设任何第三方产品的内部安全实现。用户可以选择 **每次审批、自动审批、完全访问** 三种模式。审批模式仅决定在合法权限范围内某类工具调用是否需要再次征得用户同意，绝不授予新的节点、服务组、证书、文件或组织范围权限。

### 10.5 用户界面和交互

- AI 运维页面顶部展示三张可点击的横向长方形模式卡片，明确说明批准策略；当前模式有选中标记。下方仍保留节点/服务组资源卡片、拖拽授权区、聊天框、执行计划、推荐资源及审计。
- **每次审批（默认）**：每一次真实工具调用（包括查询）都须进行单独审批；不批准不执行。纯语言聊天不属于工具调用。
- **自动审批**：允许后端白名单内的只读查询及低风险操作自动执行，其余尤其是服务重启、安装/部署、证书变更、删除等需人工逐项审批。风险等级和白名单以服务端版本化策略为准，不能由 AI 自我声明。
- **完全访问**：用户须在风险弹窗中主动确认，并选择 15、30 或 60 分钟有效期（初版可设更严格的管理员上限）；有效期内**未被硬性策略要求逐项人工批准**且在当前资源授权范围的合法工具调用可以免逐项审批。AI 发起的任意 root Shell 仍须按已批准 ADR-PRIV-001、ADR-AI-001 获得管理员在 Web 的真实确认；私有 Root CA/中间 CA 私钥导出等高危能力不能仅靠切换模式开放。账户 RBAC、额外认证和组织策略始终优先。到期后恢复「每次审批」。
- 切换审批模式时，未执行的旧待批计划应失效，避免绕过审批；开始新的 AI 会话时重置为默认每次审批且零资源授权。
- 显示当前策略、到期时间和最近审批/拒绝事件；后台存储完整可审计历史，包括操作者、时间、节点快照、工具和分类、结果与拒绝原因。

### 10.6 强制的资源与权限边界

有效工具权限 = **登录用户的原始权限 ∩ 当前会话明确授权的节点/服务组实时有效资源 ∩ 服务端允许的工具权限 ∩ 审批策略结果**。所有执行都在后端入口逐目标校验；子 Agent、插件、批量任务、异步重试及队列工作进程不得规避。

- **完全访问绝不是全局服务器访问权限**。未拖入的节点/服务组依然不可读、不可操作；不能直接要求模型访问控制端、底层数据库或 SSH 凭据绕过边界。
- 服务组授权保留既定的冻结成员快照和实时成员交集语义，新成员不自动获得权限，成员被移出后失权。
- 授权被撤销、会话结束、权限变更或审批有效期到期，应取消/拒绝尚未真正执行的请求。运行中的操作需要按照任务类型安全中断或标记取消，不能承诺任意操作一定可回滚。
- 用户无法批准超出自身 RBAC 的请求；即使用户将前端参数改成 `mode=full`、伪造 `approvalId` 或 `targetNodeIds`，后端也须拒绝。
- 高权限 Shell 的凭据、网络和横向访问能力必须额外隔离；仅基于目标 Node ID 白名单无法证明严格隔离。

### 10.7 后端接口要求

- `GET/PATCH /api/v1/ai/sessions/{sessionId}/approval-policy`：查询/切换会话模式。完全访问必须由服务端校验用户确认、审批资格及有效期上限；拒绝过期会话与越权切换。
- `POST /api/v1/ai/sessions/{sessionId}/approvals`：生成一次性审批请求，绑定工具名称、规范化参数摘要、目标节点快照、资源授权版本、用户和到期时间。
- `POST /api/v1/ai/sessions/{sessionId}/approvals/{approvalId}/decision`：用户批准/拒绝；批准仅能使用一次，不允许重放、改参或更换目标。
- `GET /api/v1/ai/sessions/{sessionId}/approval-events`：查看经用户授权的审批审计事件，支持分页。
- 保留 `/api/v1/ai/tools/execute`，由服务端根据审批模式与工具的服务端风险分类判断是否需要 `approvalId`，不能由请求中提供 `mode` 自行绕过。

### 10.8 验收场景

1. 新会话缺省每次审批、无节点授权；三种模式下尝试访问未授权节点均拒绝。
2. 授权一台节点，每次审批模式下查询 CPU → 等待批准；批准后仅返回该节点数据。
3. 自动审批模式下查询 CPU 或刷新监控 → 自动通过；重启服务 → 待人工批准。
4. 完全访问必须弹风险确认，显示有效期；授权节点上的合法操作可免逐项批准，未授权节点仍拒绝。
5. 撤销资源权限、从组移除成员、切换模式或过期后，旧计划不能被继续执行；服务器端拒绝伪造批准和间接工具调用。
6. 对同一工具调用重复使用批准凭证 → 拒绝；审计包含执行来源（自动/人工）及真实资源快照。

### 10.9 演示边界

`ServerFleet-v0.9.html` 中的模式切换、倒计时、模拟批准、模拟审计仅用于功能讨论，不代表真实后端安全隔离已经实现。真实产品必须使用服务端授权、凭据隔离、任务级审批执行器和不可由前端篡改的审计存储。

## 11. 插件仓库、按需安装及热管理（FR-PLUGIN-004）

### 11.1 产品原则

- **轻量优先**：Controller 与 Agent 的正式发布包不得预装可选插件；核心节点管理、基础监控、文件互传、任务、网关、DNS 管理、AI 运维入口不得依赖可选插件才能使用。
- 插件管理器是核心能力；打开插件中心只读取必要目录元数据，**主动安装时**才下载选定插件包，不克隆整仓库。
- 项目源码根目录包含 `Plugin/`，保存官方可选插件源码、清单与发布元数据。Controller 运行时的已安装插件应另存独立数据目录，不必与源码目录相同。
- 默认来源是项目**官方 GitHub 仓库的 `Plugin/` 目录**；当前未提供正式官方仓库 URL，因此原型显示“待绑定”，不得虚构链接。
- 开发者 Fork 官方仓库后可将自己的插件放入 Fork 的 `Plugin/`，在插件中心设置该仓库 URL 和 ref，再刷新、选择安装。
- 第一版只允许**一个当前生效仓库**，切换来源不自动替换已安装的插件。新源必须明示为第三方来源；插件绑定来源和固定版本。
- 轻量并非仅缩小 Release 包体积：未安装零插件代码加载；禁用后停止执行；可按需卸载运行实例；复杂插件可能仍消耗额外资源。

### 11.2 第一版官方插件清单状态（截至 v0.9）

- **第一版唯一正式批准的官方可选插件：Xray 节点管理器（1 项）。** 它属于产品设计与演示目录条目，**尚未编写可安装的真实插件发行包**；不可将需求批准或原型中的“模拟安装”误记为已经发布。
- v0.8 之前用于展示的六个示例插件（文件工具增强、Docker 管理、Nginx 工具增强、流量分析、安全巡检、自定义插件占位）已全部移除，不属于首版插件范围，除非未来另行审批，不得恢复。
- 插件中心的**官方目录设计清单只有 Xray 条目**；初始未安装、未启用时无插件业务菜单。若官方插件发行制品尚未生成，真实安装动作必须显示“不可安装/尚未发布”，而不能伪造下载成功。
- 保留插件平台：GitHub 官方/Fork 仓库配置、按需拉取、安装、启停、更新、卸载、来源验证、权限审计。官方 GitHub 仓库 URL 尚待绑定；用户修改仓库来源不应自动替换已安装插件。
- 从早期原型迁移时，清理已被取消的六项历史演示插件与动态菜单；不得清除真实节点、服务组、DNS、凭据元数据或用户的仓库配置。
- 该插件唯一详细功能规范：`Plugin/xray-manager/FR-PLUGIN-XRAY-001.md`；本文件第 17 章只负责集成边界。插件是否采用受控 WASM 等具体执行形态**必须经新版 ADR 审查**，不由文本收口代为批准。

### 11.3 插件类型及界面

- **声明式插件优先**：基于预置标准界面组件和受控操作描述定义按钮、表格、配置页面等。
- **受控 WASM 扩展**：需要附加业务逻辑时使用兼容 WASM 的受控执行环境；不承诺允许任意原生插件、任意系统调用或未审核的主控脚本注入。
- 插件清单需声明：ID、名称、版本、兼容的主控版本、资源类型、功能入口、所需权限、下载产物、大小、完整性校验和发布者。
- 安装时展示**来源/版本/权限**及危险提示，经管理员确认才进行安装。未安装或禁用的插件不显示其业务菜单。

### 11.4 热管理生命周期

| 动作 | 用户可见预期 | 不重启 Controller |
|---|---|---|
| 安装 | 获取包、验证签名/哈希、校验兼容性及权限、注册插件、可选择启用 | 是 |
| 热启用 | 功能入口即时出现，按需加载插件执行模块 | 是 |
| 热禁用 | 新任务停止分发，安全结束/取消进行中的任务，功能入口消失 | 是 |
| 热更新 | 锁定新版、验证、排空任务、切换、健康检查；失败维持/恢复旧版 | 是（有条件） |
| 热卸载 | 停止任务并清理运行文件；保留/清除插件数据需要用户选择 | 是 |
| 插件异常 | 不拖垮核心主控，有独立故障状态、隔离与诊断信息 | 应支持 |

**限制：**处于长事务、持续流或无法中断任务中的插件不能承诺零停顿无损更新；应延期更新或征求用户同意。WASM 的沙箱性质不代表可以无需鉴权、无需审计。

### 11.5 安全边界

插件只能通过权限控制的主控能力接口操作节点；不允许自动获得主控系统管理员或所有 Agent 的 root 权限。第三方 Fork 版本必须展示非官方来源；锁定不可变版本（如 commit/Tag 加完整性哈希），检查兼容性，防止自动执行未经授权代码。将原 ADR 关于“内置插件”的约定与“首版不打包可选插件”区分，并在实施前提出 ADR 修订。

**验收：**零安装时核心系统工作；安装后插件导航即时出现；禁用后即时消失；更新失败旧版仍可用；Fork 仓库可配置且不隐式覆盖老版本；所有变更产生审计记录。

## 12. 主控与 Agent 更新、备份（FR-UPDATE-005）

### 12.1 使用场景和入口

- **系统设置 → 系统更新** 中新增「检查更新」与「一键更新」；原「更新中心」继续保留并展示同一份状态和历史，避免两套更新配置。
- 明确区分 **Controller 主控** 和 **被控 Agent**：主控一键更新为单独的更新作业；Agent 通过现有更新中心支持选择节点与分批升级。
- 提供当前版本、目标版本、发布通道、发布时间、变更摘要、签名验证结果、兼容性检查结果、备份状态、更新进度、更新失败原因、恢复结果和审计记录。
- 检查更新不应导致安装或自动重启。第一版禁止默认静默安装，需管理员主动点击和确认。

### 12.2 主控升级的安全流程

1. 拉取可信版本清单，验证签名、哈希、防降级和目标平台兼容性。
2. 检查空间、运行状态、升级中任务和数据库迁移兼容性；不满足条件则拒绝安装并给出可处理原因。
3. 生成可验证的配置/关键数据备份（明确存储位置、保留期、校验结果）。
4. 经有权限的管理员确认后创建幂等升级作业，记录操作者、版本、版本来源和操作批次。
5. 下载安装并启动新版本，检查控制面健康、数据库可读写和已连接 Agent 的基本功能。
6. 升级失败时执行**可行的**程序与配置恢复；对不可逆迁移须在操作前明示并禁止承诺自动无损回滚。
7. 更新作业在 Controller 重启后仍须可查询，不能因浏览器断开丢失；同一时间只允许一个主控升级作业。

**验收：** 同一界面可模拟检查、安装成功、失败恢复和历史；真实实现必须通过断电/重启/迁移失败场景验证恢复能力，失败不得显示为“更新成功”。

### 12.3 备份与恢复模块

保留现有「备份与恢复」入口，展示备份记录、创建备份与恢复操作；主控更新前应完成可验证的关键数据备份。完整灾难恢复流程已被批准为 FR-0804；仍只是设计与模拟能力，真实恢复验证待后端阶段。

## 14. 统一跨模块规则与接口一致性

| 规则 | 当前生效要求 |
|---|---|
| 普通分组与服务组 | `NodeGroups` 只用于整理/筛选；`ServiceGroups` 用于业务服务、网关调度、证书下发、任务目标与 AI 授权，不共用 ID |
| 任务目标 | 提交时固化节点快照，检查每一项目标的当前权限；后台重试不自动扩权 |
| AI 会话 | 默认零节点授权、默认每次审批；审批模式绝不扩大资源或 RBAC 权限 |
| AI 完全访问 | 须风险确认及有效期；不免除已批准 ADR 规定的“AI 发起任意 root Shell 必须管理员 UI 确认”，也不能导出主控信任私钥或扩大资源/RBAC 权限 |
| 文件互传 | 必须同时授权源读取与目标写入；路径归一化和符号链接处理不依赖前端 |
| TLS 凭证 | 共享的是公开 CA 信任信息，不共享不同节点/服务的身份私钥 |
| 网关准入 | Nginx 安装成功 + 配置/服务/健康检查通过 + 在线 + 管理员启用才可进入调度 |
| DNS 凭据 | 首版 Cloudflare、多账号隔离；Token 后端安全保存、普通 API 不回显 |
| 插件 | 不预装可选插件；安装/启停/更新/卸载不重启主控；受控权限和来源校验 |
| 更新 | 由管理员确认，做兼容性/签名/备份/健康检查；不可逆迁移不能虚构无损回滚 |
| 审计 | 重要变更必须可追溯；前端模拟日志不能替代后端审计 |

**OpenAPI 契约：** `ServerFleet-API-Contract-v0.9.yaml` 是当前**管理端接口设计草案**（119 路径、151 操作），其中 Xray 命名空间与 `Plugin/xray-manager/Xray-Manager-OpenAPI.yaml` 保持一致。它不是已经部署的真实 API，也**不能替代 Agent 通信协议、认证/授权及审计的完整实现契约**。接口覆盖缺口见 `docs/CONTRACT-GAP-REGISTER-v0.9.md`，不通过 docs-r2 擅自添加接口。

## 16. v0.8 六项已批准需求（FR-0801～FR-0806）

**批准状态：六项均获得产品负责人明确批准。** 当前交互前端只演示用户流程；真实部署、云账号访问、探测流量、命令执行、凭据存储与灾难恢复均未实现。不得把“模拟成功”当作生产安全或业务验收结果。

### 16.1 FR-0801 服务发布向导

**目标和边界**：让已运行在服务组中的 HTTP/HTTPS 业务，通过现有合格 Nginx 网关、Cloudflare DNS 和证书统一配置并发布。**不负责**应用安装、构建源码、容器编排、完整 CI/CD、多活扩缩容。

**用户流程**：
1. 在「核心功能 → 服务发布」或服务组详情点击「发布服务」，填写发布名称、选择现有服务组与业务端口；向导不得静默创建一个新服务组。
2. 选择在线、Nginx 安装检查通过、未处于维护模式并允许调度的网关；失效网关不可选。
3. 填写访问域名，选择所属 Cloudflare 账号及 Zone；按需关联网关 HTTPS 证书；可选择生成服务监控草案。
4. 展示变更预览：会修改哪些网关路由、DNS 记录和证书引用；列出已有同名记录、权限/容量/健康风险，要求具有权限的管理员确认。
5. 创建可追踪异步发布作业，分阶段记录预检、网关配置、DNS/证书、外部可用性验证、最终状态。
6. 完成后保留发布记录、操作人、变更摘要与受影响资源；失败时提供按阶段修复或**可行的**恢复操作。

**强制业务规则**：网关准入、健康成员数、证书状态及目标 Zone 写权限都必须由服务端验证；幂等请求防止重复发布；服务组目标为稳定 ID，配置引用不存在时拒绝。跨 DNS/网关/证书的多步骤发布不是原子数据库事务，局部失败不能报告“全部完成”；DNS TTL 缓存使即时全网回滚不可保证。需要明确“已提交、部分完成、验证失败、完成、需人工修复”状态。来自 AI 的发布操作仍受会话节点授权和审批等级约束，不可借网关间接访问未授权节点。

**与现有模块关系**：服务组提供后端成员和端口；网关提供入口与路由；DNS 提供 Cloudflare 账号/Zone/记录；证书提供公网 HTTPS；监控提供发布后检测；统一后台作业、审计提供可追踪状态；不产生第二套 DNS/证书权威配置。

**MVP 验收**：至少可模拟完整的四步向导、准入拒绝、变更摘要、发布记录和部分失败说明。真实验收应验证幂等、权限、DNS 延迟、网关检查失败及发布后健康检查。前端演示中的 DNS、证书、Nginx 操作始终为模拟。

### 16.2 FR-0802 服务可用性监控

**页面位置**：「监控告警」内部改为「资源监控 / 服务监控 / 告警事件」分区；保留已有资源监控功能。监控对象可关联节点、服务组、网关或独立 URL。

**用户流程**：新建检查 → 选择 HTTP/HTTPS、TCP、TLS → 填写访问目标、探测来源、间隔与超时 → 指定连续失败/恢复次数 → 选择 QQ Bot/SMTP 通知规则 → 保存后进入待确认状态 → 查看探测历史与异常/恢复事件 → 支持暂停/恢复/删除。默认建议 60 秒间隔、5 秒超时、3 次连续失败判异常、2 次连续成功判恢复，用户可调整。

**状态和规则**：正常、异常、待确认、未知、已暂停必须严格区分；探测节点失联、DNS 无法解析或监控运行器宕机不能自动判定被监控业务失败。监控来源必须具有执行该检查的权限，禁止利用内网探测进行未经授权的目标扫描；目标地址需要 SSRF 防护及目的地限制。HTTPS 检测与证书剩余有效期检查在 UX 上分开。通知按事件去重、限制重试频率，维护窗口只静默通知不删除历史数据。发布向导可生成关联监控草案，但不得隐式创建未授权外部扫描任务。

**与已有模块关系**：网关健康检查用于决定后端调度资格，服务监控面向最终服务可用性，二者不能混淆；复用通知、告警和审计，AI 只能阅读本会话授权范围内相关监控；服务组的健康展示引用已有监控结果，不再自建一份矛盾状态。

**MVP 验收**：可建立、暂停、删除三种检测类型；连续失败/恢复状态判定正确；探测来源离线显示未知；多次相同故障不产生告警风暴；正式接入前完成内网目标授权和 SSRF 负面测试。

### 16.3 FR-0803 批量任务安全执行

**页面位置**：「批量任务 → 创建任务」增加安全策略，不新建任务引擎。任务范围可来自单节点、多节点、自定义节点分组或服务组，提交时冻结目标 nodeId 快照。

**用户流程**：选择目标 → 配置命令/预定义操作 → 选择「普通、分批、金丝雀」策略 → 设置批量大小、并发上限、失败熔断阈值、有效期/超时 → 查看影响范围和可预演性 → 按权限审批 → 分阶段执行并查看逐节点结果。金丝雀默认先执行 1 台，经健康检测再推进后续批次；普通执行并非无限并发。

**强制规则**：前端选择不代表授权，创建任务/每批执行/每台执行前服务端均校验用户角色、节点与服务组成员资格、审批有效期。服务组新增成员不会扩大旧任务，退出成员与撤销权限要使待执行部分立即失效。预演须区分「可预演、部分可预演、不支持预演」，对任意 Shell 不承诺可预测所有副作用。失败达到阈值立即暂停**后续**节点；停止执行不等于自动回滚。离线待执行任务必须有 TTL，到期后拒绝，危险任务重连后需要重新审批。影响可用后端容量的操作应检验是否留有健康服务节点；所有任务仍遵守 AI 资源沙箱与三级审批硬边界。

**与已有模块关系**：节点列表/普通分组/服务组提供选择范围；网关在必要时可对目标节点进行维护排流；服务监控提供批次健康信号；统一审计记录单台结果；插件/AI 发起的任务同样经过统一执行策略。

**MVP 验收**：金丝雀失败不推进第二批；失联重连不补执行过期危险任务；模拟取消/暂停/审批失效有可追踪记录；不承诺通用命令自动回滚或完美预演。

### 16.4 FR-0804 节点恢复与主控灾难恢复

**节点连接诊断入口**：「节点管理 → 节点详情 → 连接诊断」。显示最近心跳、连接质量、可验证身份状态、待执行任务有效期与诊断原因；主控失去心跳只能报告**失联**，不能推断节点关机。重连必须重新验证身份；已撤销凭据不可恢复；过期任务废止，危险任务等待重新审批；节点重装沿用已批准引导和吊销流程。

**主控恢复入口**：「备份与恢复 → 主控灾难恢复」，在新安装的主控上也必须存在恢复引导。用户应能选择备份、查看类型与备份时间、校验完整性与恢复密钥、预览待恢复的节点身份/配置/权限/插件数据、确认旧主控隔离、启动恢复作业、检查 Agent 重连和失败节点。备份版本与主控版本不兼容时禁止强行恢复。不可逆数据库迁移必须预警，并提供人工恢复指导。恢复目标中的 RPO/RTO 是待实测 SLA，不得承诺未经实测的指标。

**PKI 约束**：不得把离线 Root CA 私钥放进普通自动备份；在线签发凭据需要专门加密与恢复流程，证书吊销、节点迁移与 CA 连续性遵守原 ADR。旧主控与新主控不得同时以同一身份下发管理指令；仅让用户勾选“旧主控已经停止”并不足以在正式系统证明已安全隔离，应有可校验的切换/租约或人工受控步骤。

**与已有模块关系**：节点列表/添加节点/PKI/任务中心提供状态与历史；更新中心的升级前备份与备份恢复使用同一个备份注册表；凭据管理为恢复后的秘密引用提供恢复/轮换流程；审计记录每次恢复和失联处置。

**MVP 验收**：支持离线诊断与安全重连；人工备份校验与新主控恢复引导；备份损坏、恢复密钥缺失、双主控冲突、部分 Agent 重连失败都能明确报告。首版不包含多活控制面或无人值守故障切换。

### 16.5 FR-0805 安全凭据管理

**入口**：「系统设置 → 安全凭据」，与业务模块中的凭据选择器联动。支持 Cloudflare API Token、SMTP 密码、QQ Bot AppSecret、AI 模型 Key 等；不将离线 Root CA 私钥视为普通 Web 凭据。原型仅保存凭据元数据，不收集真实秘密。

**用户流程**：添加凭据名称/类型/用途 → 安全写入秘密 → 绑定允许使用的业务功能及最小权限 → 验证凭据可用性 → 保存只读元数据 → 查看引用关系/有效性 → 轮换或紧急撤销。正常轮换先验证新凭据，再切换引用，最后撤销旧凭据；已泄露凭据应优先紧急撤销。

**硬性约束**：服务端加密托管并严格控制解密/调用，API GET、日志、审计、AI 输入和插件回调不得返回凭据明文。AI「完全访问」只改变其既有资源与工具操作审批，不赋予密钥导出能力；插件必须通过受控能力接口间接操作，不直接获得 Token。凭据撤销后所有引用的操作必须被阻止或进入需要修复的状态。备份恢复应保护凭据加密材料和恢复权限；多租户/多用户读取需按授权范围过滤。

**与已有模块关系**：DNS、SMTP、QQ Bot、AI、插件仓库的业务配置引用凭据 ID；用户与权限决定谁能创建/轮换/撤销；审计记录操作而不保存敏感值；现有私有 CA 的根密钥仍依原独立管理方案存放。

**MVP 验收**：普通查询不可回显秘密，撤销凭据后依赖操作失败且提示，删除前列出引用，未授权用户/AI/插件读取秘密被服务端拒绝。仅凭前端隐藏输入框不构成安全验收。

### 16.6 FR-0806 流量配额与到期提醒

**入口**：「节点详情 → 流量与配额」，节点列表展示使用率与风险，首页展示临近配额/到期节点，通知继续使用 QQ Bot/SMTP。

**用户流程**：为各节点分别填写配额（GB）、计费方向（入站/出站/合计）、统计来源、周期重置日和时区、实例到期/优惠额度到期类型、到期提醒提前天数、流量告警阈值（建议 70/85/95%） → 观察本周期用量和数据完整性 → 按阈值接收通知 → 查看预测（历史充足时）。默认**仅提醒，不自动断网、续费或购买流量**。

**关键边界**：Agent 网卡数据与云平台计费口径可能不同；没有云账单数据时只能明确写「估算值」，不能声称实际账单或准确剩余额度。节点离线时标注数据缺口，不填造零流量。计费周期不假设所有 VPS 在每月 1 日重置；支持独立的周期与时区。预测必须注明样本范围，数据不足时显示不能估算。实例到期、试用结束、信用额度结束、流量重置是不同事件，不能混为关机时间。

**与已有模块关系**：复用 Agent 资源采集，节点资产记录套餐信息，监控告警生成阈值事件，QQ/SMTP 发送提醒；AI 只能访问已授权节点的流量数据；未来云平台账单适配作为独立能力扩展，不改变本版节点信息模型。

**MVP 验收**：每台节点具有独立配额与周期，离线显示缺失，达到阈值避免重复告警，提醒不会自动关机；用户可以修改到期提醒并看到更新后的风险状态。

### 16.7 本轮统一的跨模块约束与实现顺序

- 未批准的完整 CI/CD、全球多点 SLA、自动多活/主控选举、通用脚本回滚、云账单 API 自动集成、复杂 APM 与配置漂移检测，不得通过本次“全部批准”暗中纳入范围。

### 17.1 已批准的第一版功能范围

- 多节点 Xray-core 安装、接管前确认、检测、更新、启停和节点级卸载（**卸载节点上的 Xray 与卸载插件是不同操作**）。
- 标准 `VLESS + TLS + Vision`、`VLESS + REALITY + Vision` 两套版本化配置模板，支持自定义 Xray JSON 配置。
- 配置预检、目标版本 `xray run -test`、差异预览、审核确认、分批/金丝雀发布、配置历史和失败恢复。
- 用户身份创建、变更、禁用、持久配置同步、受控客户端连接参数导出。
- 节点、入站、用户三级代理流量统计；识别重启/计数器重置和采样缺口，区分代理统计与服务器网卡/云账单统计。
- 对接系统节点/服务组、后台任务、TLS 证书、安全凭据、流量配额、QQ/SMTP 通知、RBAC、AI 会话授权与审计。

### 17.2 限制和不包含的功能

- 插件始终按需下载与启停，**不打包进 Controller/Agent 核心 Release**；未安装不加载业务插件代码。
- 初版一个节点默认只托管一个 Xray 实例；发现已有实例时默认只读检测，不能未经确认覆盖现有服务或配置。
- 主控插件卸载不自动卸载 Xray-core；REALITY/用户凭据和 TLS 私钥不得进入普通 GET、日志或 AI 提示词。
- 不包含完整订阅门户、收费系统、流量自动封禁、跨云账单对账、自动多协议切换、多实例复杂编排或防封锁效果保证。
- 首版声明式界面与受控扩展，不授予任意主控脚本或 Root/Shell 权限。批量任务固定目标快照，并严格执行 AI 资源范围和三级审批规则。

### 17.3 需求与 ADR 一致性

Xray 插件安装受控软件、维护服务和统计时可能需要新增 Agent 白名单能力。在实施前对既有 `ADR-PRIV`、`ADR-PLUGIN`、`ADR-TASK`、`ADR-AI` 做差异核对；如有冲突必须提交正式 ADR 修订，不能因用户批准产品功能而默默扩大已批准权限。原型仍只模拟行为，没有真实后端执行器。
