# ADR-AI-001 / ADR-PRIV-001 — 三级审批与强制安全边界解释性补充

- **状态**：Accepted（2026-10-29），解释性补充，不替代既有权限模型。
- **适用产品**：Server Fleet v0.9 及后续版本。
- **目的**：澄清较新的「每次审批 / 自动审批 / 完全访问」产品交互与早期“任意 AI root Shell 必须人工确认”的安全要求的关系。

## 1. 权限和审批是两层不同的检查

工具是否可执行 = 登录用户的当前 RBAC 权限 **∩** 会话授权的有效节点/服务组快照 **∩** 插件/工具细分权限 **∩** 服务端不可豁免限制 **∩** 当前操作所需审批。**审批模式本身不能增加可访问节点、文件、凭据或操作类型。**

1. 新 AI 会话默认**零授权资源**、`每次审批`；从服务组拖入时冻结成员快照，新增成员不自动授权，成员移除后立即失权。
2. `自动审批` 仅可跳过服务端白名单内的低风险、适当脱敏的只读操作；AI 模型不能自报风险等级或自发批准。
3. `完全访问` 需要有资格的用户显式确认，限时 15/30/60 分钟（可由管理员下调），只在**授权资源、受限能力和组织政策范围内**减少可豁免操作的逐项确认；到期后恢复默认模式。
4. **任何由 AI 发起的任意 root Shell 必须经过具有权限的真实管理员 Web UI 人工批准**，即使在完全访问期间也不能豁免。
5. 私有 Root CA 私钥、离线恢复解密私钥和平台原始 Token/密码等**不向 AI 提供直接明文查询/导出工具**；需要用受控凭据的操作只能经指定业务服务使用，不得将明文传递给模型。
6. `插件禁用`、`会话撤权`、`组成员移除`、`权限撤销`、`审批到期` 必须阻止后续待执行或新派发动作；已经运行的操作按照真实可取消性尽力中断，不能宣称任何副作用均可回滚。
7. AI、子 Agent、插件、后台重试、定时任务通过统一受控能力入口执行；前端按钮隐藏或提示词不能代替服务端鉴权。
8. Root Shell 的网络横向访问、继承的宿主凭据和外部副作用不能仅靠 Node ID 白名单得到完全隔离；G2 权限与 Agent 执行沙箱/网络限制应给出真实风险边界。

## 2. G2 所需的负向验收

- 伪造 `mode=full`、`approvalId`、未授权 `nodeId`、已经撤销的 `scopeRevision` 均在服务端拒绝。
- 撤销授权后旧任务不得因重试/重连重新执行；审批不得重放或改参后使用。
- 将旧会话 Xray 插件请求重新送到禁用后的插件端点，必须拒绝。
- 完全访问期间请求未经批准的任意 root Shell，仍应等待管理员明确批准，不得派发 Agent。
- 任何 API/日志/模型上下文不得显示 Root CA 私钥、恢复解密私钥或 Token 明文。

**状态**：只将已批准规则解释清楚；不增设自动 sudo Helper、不擅自变更 root Agent 既有运行模式。
