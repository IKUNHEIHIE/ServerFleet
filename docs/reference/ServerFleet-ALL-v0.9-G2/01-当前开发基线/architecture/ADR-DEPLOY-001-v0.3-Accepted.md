## 1. 新的两条明确路径

**A. 安全接管既有 Nginx**：发现服务与版本、监听/端口和未受管配置→检查冲突→管理员确认纳管范围与受管 include 目录→语法/服务/连通性验证→可管理；保留历史站点与第三方配置，绝不无提示覆盖。现有 Nginx 不因注册成为网关就被自动安装或替换。

**B. 经授权全新安装 Nginx**：只允许当前在线、授权充足、OS/CPU 架构与软件包来源受支持的节点；预检包管理器、磁盘、端口、已有软件和潜在业务冲突；管理员确认变更范围后创建任务，经可信仓库/包校验安装；随后验证安装、配置、服务、监听与必要连通性。安装失败进入故障状态并记录诊断，只清理**本轮确切创建且不影响旧业务的资源**。

## 2. 调度准入与状态

必须分别展示：`未发现`、`预检查失败`、`安装中`、`已安装待验证`、`已验证待启用`、`维护中`、`可调度`、`失败待处理`。只有在节点在线、Nginx 服务和配置检查通过、后端可达/健康策略符合要求，且管理员**明确启用**之后，网关才能进入调度候选。安装成功**不意味着**已经承担生产流量。

## 3. 保留的不变量

- 主控是控制平面，用户 HTTP/HTTPS **不经过主控**，仍走真实 Nginx 网关节点。
- 多入口 Nginx 反向代理的后端必须是已注册、已授权、真实网络可达的服务；Agent mTLS 控制连接不是 TCP 数据隧道。
- Nginx 配置隔离到 Server Fleet 受管片段，必须 `nginx -t`、平滑 reload、部署后探测；失败尽力恢复上一受管版本。
- 公网 TLS 私钥每个入口独立、本地保管；DNS/ACME 由主控协调，Cloudflare Token 不放在网关 Agent。
- Web、AI 与插件全部走统一任务、1→5 分批、服务端授权、审计和失败处理。
- 不实现任何未经批准的主控 Nginx 数据面、Nginx stream 透明隧道、自动跨云网络穿透或商业级自动摘流承诺。

## 4. 验证与后续契约

PoC-05 测试“未安装、已安装、端口冲突、不完整安装失败、配置已有冲突、维护态/离线不调度”。G2 需要分别定义 `adopt` 与 `install` 作业、状态转移、目标端口冲突、卸载影响提示、调度准入门槛与 API 权限。失败时不承诺完整撤销系统包管理器的所有副作用。
