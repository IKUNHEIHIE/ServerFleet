## 1. 问题与取舍

旧 D2 把可选业务插件后端编译进主控 Go 二进制，无法真正实现“无需重编主控、在启用时才安装插件业务代码”。后续明确批准的产品要求优先：**核心二进制不预装可选业务插件，按需下载、安装、启停、更新和卸载**。但第三方原生代码的执行风险及轻量化必须受控。

## 2. 正式替代条款 PLUGIN-D2（v0.3）

1. Controller Release 内只含：插件管理器、版本/来源/清单验证、声明式 UI 统一渲染器、受控数据源和动作分发接口、权限/审计/任务集成。**可选 Xray 业务包不可被预编译进入核心 Release。**
2. 插件包通过官方 GitHub `Plugin/` 或经管理员指定的单一 Fork 来源获取；来源 URL、仓库版本/commit、发布产物 digest、发布者、权限和兼容范围必须可审计；从 Fork 下载**不等于可信**。无可验证签名/预设信任时不得假装为“官方验证”。
3. UI 只支持 JSON/YAML → 严格 Schema → 主控 React 组件渲染；不安装浏览器 JS/HTML、自定义 React、iframe 或任意内联执行脚本。
4. 无业务逻辑的扩展优先使用声明式动作；需要额外计算时，首选**受限 WASM + 版本化、类型化 Host Capability** 进行独立 PoC，不预设该方案已经生产可用。
5. WASM 运行单元默认**无文件系统、网络、进程启动、宿主环境变量或密钥读取能力**；任何能力都需要显式授予并经过同一服务端 RBAC、节点作用域、插件权限、任务审批。所有涉及节点实际更改的调用都进入统一任务引擎和 Agent 受控动作，不可直连主控 mTLS 通道。
6. 必须为插件运行时间、内存、调用频次、并发和日志设置硬性限制，异常任务可取消，禁用后立即拒绝**新业务动作**；在途执行遵照统一任务安全取消/收尾，不承诺可无损停止。
7. 热生命周期：锁定来源和版本→验签/摘要/兼容检查→权限确认→启用；更新时暂停新任务、排空/安全中止在途任务、切换、健康验证、失败时恢复旧版；删除插件时**不默认卸载已安装在节点上的 Xray 服务及其业务配置**，保留/删除插件托管数据须用户明确决定。
8. 第一版只批准 `xray-manager` 为可选官方插件；不预装原先已移除的六项演示插件，不声称市场中存在可以安装的真实插件发行产物。

## 3. 受控 Host Capability 示例（仅能力方向，非 API 冻结）

- `managed-package.inspect/install/update/uninstall`：指定受支持的已批准软件包与来源，禁止任意来源脚本。
- `managed-config.validate-and-apply/rollback`：只操作已授权受管目录、校验版本和差异，保留上个有效配置。
- `managed-service.inspect/start/stop/restart`：只允许登记服务和被授权节点。
- `managed-stats.read`：从节点回环或受限 Unix socket 读取 Xray 统计；默认禁止公网监听 API。
- `jobs.submit/read`、`credentials.use`、`audit.emit`：权限约束的主系统能力，**不得通过 `credentials.use` 返回密钥原文**。

这些名字不是可直接实现的正式 SDK 规范；G2 定义参数、幂等、错误、权限、审计和版本兼容。

## 4. 未解决且不能擅自决定的实现细节

- WASM Engine 与资源预算、可中断性、宿主调用 ABI、冷热启动性能；应优先评估 wazero，但不能因推荐就锁定。
- 用户自定义 Xray 配置在受限操作模型中的安全边界，及其是否需要少量额外类型化 Agent 操作。
- 插件包的官方签名信任根、Fork 可信策略、依赖完整性校验和撤销机制。
- 若 WASM 方案 PoC 失败，**须提交新 ADR** 评估受限独立进程/RPC；不默认安装任意二进制以替代。

## 5. 强制验收与生效范围

必须通过 PoC-01/02/03/04、失权/插件禁用负向测试，并检查 1C1G 的 RSS/CPU、运行中取消、更新失败恢复和源码/产物校验。**此 ADR 自批准日起替代旧 D2 的发行形式要求；选择某个具体 WASM Engine 和生产执行模式仍待 PoC。**
