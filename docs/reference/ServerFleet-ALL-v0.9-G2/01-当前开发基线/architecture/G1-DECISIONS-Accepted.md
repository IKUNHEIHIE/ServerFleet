# Server Fleet — G1 架构决策批准记录

- **状态**：**Accepted / 用户正式批准**
- **批准日期**：2026-10-29
- **产品基线**：`Server Fleet v0.9 / docs-r2`，功能范围不变
- **批准范围**：G1-D1～D6 全部按 `G1-Decision-Sheet.md` 的推荐方案批准
- **证据**：项目所有者回复“技术方面我啥也不懂，按照你推荐的来”，对紧邻的 G1 六项推荐作出整体批准。
- **重要区分**：**架构治理方向获批 ≠ PoC 通过 ≠ G2 API 冻结 ≠ 功能开发完成。**

## 六项正式决定

| 编号 | 已批准架构方向 | 仍需验证/未锁定的部分 |
|---|---|---|
| G1-D1 | Go 模块化单体 Controller、轻量 Go Agent、React/TypeScript/Vite + shadcn/ui、SQLite WAL、Agent 主动 mTLS + Protobuf、管理事件 SSE | 资源上限、数据库吞吐及运行性能未实测；不承诺已满足 1C1G |
| G1-D2 | 可选插件不进入核心 Release；声明式 UI + 受控 WASM 作为**第一候选 PoC**；不得采用 Go 原生 `plugin` 动态库作为第一版运行模型 | WASM 运行、隔离、Host API、热更新需 PoC；失败需新 ADR 评审受限子进程/RPC，不能自行更换或宣布已通过 |
| G1-D3 | 网关提供“已有 Nginx 安全接管”和“经批准全新安装”两条路径，健康检查与管理员调度准入分离 | 安装兼容性、端口冲突与失败清理由 PoC 验证 |
| G1-D4 | AI 三种审批模式独立于授权范围；“完全访问”不能绕过节点 RBAC、AI 任意 root Shell 的真人审批、敏感凭据禁止直出 | 服务端权限负向测试、撤权及异步任务校验 |
| G1-D5 | BOOT、PRIV、TASK、WC、PKI-OPS、UPDATE 的不冲突条款及已批准默认值继续生效 | 实施细节仍需在 G2 映射到统一契约 |
| G1-D6 | 设置 PoC-01～08 的明确验收门槛，先出证据，再宣告运行模型最终冻结 | 所有 PoC 未执行，尚无运行性能、隔离或恢复能力的实测结果 |

## 决策效力与历史保留

1. [ADR-PLUGIN-001 v0.3](./ADR-PLUGIN-001-v0.3-Accepted.md) 仅替代 v0.2 中“第一版可选插件业务后端必须编译入主控”的 PLUGIN-D2 旧规定；其他未冲突条款继续有效。
2. [ADR-DEPLOY-001 v0.3](./ADR-DEPLOY-001-v0.3-Accepted.md) 仅扩展 v0.2 “只能接管已存在 Nginx”的安装约束；其余控制/数据平面、安全配置等原决定继续有效。
3. [AI/PRIV 解释性补充](./ADR-AI-PRIV-001-Approval-Interpretation-Accepted.md) 不放松任何既有安全控制。
4. 历史原文存放于 `architecture/history/`。原始 ADR **不得静默编辑或删除**。本包仅包含本次已取得的部分原文，其他 ADR 仍须按原项目归档核验。
5. 如新技术测试失败，应新建带原因与替代方案的决策记录，经项目所有者确认后变更；不能把 PoC 失败自动当成许可改用另一架构。

## 关卡状态

- G0：产品需求收口完成。
- **G1：架构方向经批准（Accepted）；实施型技术冻结待 PoC-01～08 证据。**
