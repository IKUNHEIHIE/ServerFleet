# Server Fleet G1 — 供项目所有者逐项审批的决策清单

**全部选项为建议，不代表审批完成。** 适用产品基线：v0.9/docs-r2。

| 决策 ID | 建议选项 | 主要代价 / 风险 | 建议结论 |
|---|---|---|---|
| G1-D1 | 保留 Go 主控、轻量 Go Agent、React/Vite、SQLite WAL、mTLS+Protobuf、SSE | 仍需压测 SQLite 与长连接；各组件需版本化 | 批准 |
| G1-D2 | 可选插件采用声明式页面 + 受限 WASM 作为首选 PoC；失败时评估隔离进程，不使用 Go 原生动态 plugin | WASM 需要 Host API 边界与可靠热更新逻辑，不能保证自带 OS 级隔离 | 批准有条件研究与 PoC，不直接锁定为最终实现 |
| G1-D3 | 网关区分已有 Nginx 安全接管和新节点安装；必须健康/检查通过并人工启用才调度 | 多一步确认和失败清理流程 | 批准 |
| G1-D4 | AI 完全访问不扩权限；任意 AI root Shell 仍每次真实人工审批 | “完全访问”与用户直觉存在差异，必须提示说明 | 批准 |
| G1-D5 | 保留 BOOT、TASK、PRIV、PKI-OPS、WC、UPDATE 等 ADR 未冲突条款 | 保持旧行为约束，有实现成本 | 批准 |
| G1-D6 | 把 PoC-01～08 作为运行模型和正式冻结的证据；G2 完成契约冻结后才全面并行开发 | 开始业务开发之前需要额外短验证阶段 | 批准 |

**建议的审批回复**：

- `G1-D1～D6 全部按建议批准，WASM 先做 PoC，最终实现以验证结果为准。`
- 或者逐项说明需要修改的决策，例如 `G1-D2 改成独立进程优先，其余批准。`

批准后：正式生成带 supersedes 字段的 ADR-PLUGIN-001 v0.3、ADR-DEPLOY-001 v0.3、AI/PRIV 附录；不删除旧历史。然后推进 G2 API 与 Agent 通信契约，M0 只在核心契约达到准入要求后开始。
