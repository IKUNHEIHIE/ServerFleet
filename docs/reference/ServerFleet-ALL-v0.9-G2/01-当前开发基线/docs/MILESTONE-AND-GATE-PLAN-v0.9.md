# v0.9 产品功能冻结与建议开发分期（G0～G3）

**重要：** 全部已批准功能仍在第一版的**产品范围总清单**内。本文件给出**建议施工顺序**，并不重新定义或删减用户已经批准的功能。里程碑划分尚未被项目所有者单独批准，不能由开发 Agent 直接当作最终工期承诺。

## G0 产品功能收口（本次 docs-r2）

- 已建立统一现行 PRD、唯一插件子规范、产品历史、验收矩阵与新增/未批准分界。
- 现行获批官方插件 **1 项：Xray 节点管理器**；真实安装包数量仍为 0。
- 不额外增加功能，不选择执行架构，不修改 API operation/schema 的含义。
- **结论：文档勘误与产品范围对齐完成；产品要求冻结为 v0.9，技术方案及开发任务划分未冻结。**

## G1 架构一致性（2026-10-29 架构方向已批准；技术验证仍待完成）

- 完成 ADR-PLUGIN 更新：按需加载、热生命周期与可信执行模型；保留声明式 UI 和统一授权。
- 完成 ADR-DEPLOY 更新：Nginx 自动安装 vs 既有受管配置保护。
- 发布 AI/PRIV 不可绕过强制审批的正式解释；将安全凭据、Xray 管理动作纳入最小权限边界。
- 校验 PKI/任务/证书默认值未被新文档无意改写。

**状态更新**：上述架构修订和解释已获批准，详见 `../architecture/G1-DECISIONS-Accepted.md`；但 PoC-01～08 尚未执行，不能把“方向批准”作为运行时安全/性能测试通过。

**实际业务功能启动条件**：相应 PoC 与 G2 契约通过后才能进入正式实现；不依赖待定接口的基础工程及隔离 PoC 可先行。

## G2 接口冻结（需要新增正式 API 变更提案）

- 管理端 OpenAPI 补齐认证/RBAC/审计、节点完整生命周期、任务事件及取消、AI 消息、证书和备份操作。
- 单独建立 Agent–Controller Protobuf 通信消息与版本协商文档。
- 建立插件清单 Schema、权限能力、UI Schema 与热生命周期的接口规范。
- 整理统一错误响应、分页、幂等、并发版本与任务状态；对现有 `/tasks` 与历史 `/jobs` 选定一个**唯一**正式接口命名。
- 契约 lint、示例与权限负向测试通过后才能称“接口已冻结”。

## G3 建议的研发分期（待确认）

| 阶段 | 目标 | 最小可验证结果 | 依赖 |
|---|---|---|---|
| M0 | 工程与约束基座 | Go/React 工程、规范化协议生成、基础 UI、静态测试/CI、职责与安全边界 | G1 最小决策、G2 核心契约 |
| M1 | 最小可用群控闭环 | 管理员登录 → Agent 安全接入 → 节点真实心跳/基础指标 → 限权任务/审批 → 审计 → 基础备份 | 节点、用户、授权、任务契约 |
| M2 | 全面核心运维功能 | 文件互传、分组/服务组、网关、DNS/证书、监控/通知、AI、凭据、发布向导、系统更新、恢复及流量配额 | M1 稳定、相关 ADR |
| M3 | 第一版唯一插件和集成验证 | Xray 按需安装、配置部署、用户管理、代理流量与任务安全测试；插件热生命周期 | G1 插件 ADR、M1 任务/权限、M2 必需服务 |

**允许并行的早期 PoC：** 可以针对 Xray 固定版本配置、插件运行开销、Agent 协议做隔离验证，不因此提前声称生产功能已交付。

## 里程碑验收门槛

- **安全：** 未授权、失效审批、越权插件、伪造节点身份、重复任务都必须在服务端拒绝。
- **恢复：** 任务不确定结果、Agent 断线、更新或配置失败、恢复私钥缺失等异常必须准确展示，不得伪造成功。
- **轻量：** 1C1G 场景须实测 Controller/Agent 的 RSS、CPU、心跳带宽、历史数据增长；数值目标经测试再签署，不在此虚构达标。
- **一致：** 前端操作、OpenAPI、Agent 通信契约、真实状态机和审计至少由一条端到端测试覆盖；原型只是交互基准。
