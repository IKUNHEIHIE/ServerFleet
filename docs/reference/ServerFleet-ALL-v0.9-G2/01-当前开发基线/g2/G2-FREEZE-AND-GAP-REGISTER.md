## 四个明确不应被混淆的“冻结”

1. **产品功能**：v0.9 已批准，未在 G2 新增第 2 个插件或其他业务。
2. **架构原则**：G1 已批准，WASM/Eino 的具体生产 Runtime 尚未获 PoC 支持。
3. **基础接口草案**：G2 目前新增 34 个候选操作，**不等于冻结**，因为旧状态模型尚不一致。
4. **生产实现**：尚未通过任何真实 Controller/Agent、安全/性能联调；源码文件不是运行成功证据。

## 进入 M0 的分级准入建议

- **允许先做 M0 工程脚手架**：Monorepo、CI、Go/TS 分模块、静态前端、OpenAPI/Proto 校验工具、Mock 数据和负向测试框架。**不能把未冻协议绑定为无法修改的真实分发系统**。
- **允许先做 M1 安全闭环**：G2-C01～C07 的 API/协议冻结通过，并有 BOOT/PRIV/TASK 的必需安全测试，方可连接真实 Agent 处理高权限任务。
- **允许开始插件功能联调**：G2-E01/02 的 WASM 和 Xray 配置、统计 PoC 通过后，才选择最终 Host ABI/运行机制并发布插件。

## 建议的 G2 决策问题（技术审查人员处理）

1. 浏览器 Cookie + CSRF，受限 Bearer 给脚本/内部调用是否符合前后端部署模式？
2. `/tasks` 是否作为唯一公开规范名称，历史 `jobs.submit` 作为内部能力/别名文本而非第二套 API？
3. Protobuf major/minor、Agent 证书映射以及恢复后暂停任务规则如何做真实集成验证？
4. 先只冻结 C01～C07，扩展 E01～E08 按 PoC 逐项冻结，是否符合首版交付安排？

**推荐：接受上述四项作为 G2 初步设计方向，但正式冻结应以合同测试证据为准。**
