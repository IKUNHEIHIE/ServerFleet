# ADR-PKI-OPS-001：主控备份、私有 PKI 恢复与灾难迁移

- **项目**：Server Fleet（自托管 Linux VPS 群控）
- **版本**：v1.0 已批准记录（由独立审核草案 v0.1 提升）· 2026-10-26
- **状态**：**Accepted / 已批准**。项目所有者于 2026-10-26 批准 PKI-OPS-D1～D8，纳入 Server Fleet 文档 v1.0。**这是设计决策批准，不表示代码已开发或灾难恢复演练已通过。**
- **依赖已批准 ADR**：BOOT-001（离线 Root CA、在线 Intermediate CA、固定私有根指纹、Agent 出站 mTLS、稳定域名）、PRIV-001（单 root Agent）、TASK-001（任务幂等/未知状态/15 分钟 TTL）、WC-001（节点网站私钥不上传主控）、AI-001（AI 无权绕过审批）、UPDATE-001（发行签名、Agent 身份与二进制分离）。

## 1. 目标及非目标

**目标**：主控单机磁盘损坏、VPS 被删除或需要迁移时，管理员在新 Linux VPS 上部署兼容版本主控、导入可信加密备份、恢复域名指向，使仍持有合法证书的原有 Agent 自动重连，尽可能保留节点分组、用户授权、证书签发/吊销、任务历史及必要服务配置；不要求对每个 VPS 重装 Agent。

**非目标**：不实现自动高可用集群、双主切换、实时异地镜像、Root CA 在线托管、数据库零数据丢失保证、任意网络故障下保证重连、对已过期/泄露节点证书无条件放行。控制端恢复不能恢复 Agent 本地丢失的私钥、节点网站 TLS 私钥或被控 VPS 的系统数据。

## 2. 关键背景及不可变约束

1. Agent 固定私有 Root CA 公钥 SPKI SHA-256 指纹，通过原通信域名（示例 `agent.example.com`）验证有效的 `serverAuth` 证书链；主控更换公网 IP 不等于更换根信任。
2. 私有 Root CA **私钥离线保存**，不进入主控日常备份包、主控磁盘或 AI/插件接口；可在受控离线恢复程序中签发新的 Intermediate CA。
3. 主控拥有需要保护的在线 Intermediate CA 签发密钥；如泄露不能简单“恢复完毕”，须评估吊销、替换和信任风险。
4. Agent 证书身份与主控数据库中的 Node ID、授权状态、吊销状态同时校验；只恢复 CA 而没恢复节点状态不构成完整恢复。
5. 主控公开管理 HTTPS / Cloudflare ACME 与 Agent 私有 mTLS 是不同信任域，不能混为一谈；普通网站 TLS 私钥保留在 Agent 本地。
6. 备份的数据库历史可能落后于灾难前状态，恢复不能无条件恢复已撤销节点或自动补派旧任务。

## 3. 正式批准的八项决策（PKI-OPS-D1～D8）

| 决策 | 已批准方案 | 成本 / 权衡 |
|---|---|---|
| **PKI-OPS-D1：备份范围** | 形成**加密的主控恢复包**：用 SQLite 在线备份接口创建一致性数据库快照，连同配置、Root **公钥证书/指纹**、在线 Intermediate 私钥及证书、必要的密钥封装/凭据恢复材料、ACME 账户资料、插件配置、schema/版本、校验清单一并保存；**不包含离线 Root 私钥、Agent 私钥与 Agent 本地网站私钥** | 少量附加文件和恢复清单；需识别敏感资料。
| **PKI-OPS-D2：备份频率** | 默认**每日自动加密备份一次**；主控重大升级/CA 轮换前额外备份；默认保留最近 **7 份日备份 + 4 份周备份**，参数可调，容量有限制 | 最长可能丢失备份间隔内的业务变更；不承诺零丢失。
| **PKI-OPS-D3：异地存放** | 至少配置一个**离开主控 VPS 的备份目的地**。首版建议支持管理员下载、**SFTP 到自有另一台 VPS**；本机副本只是缓存；对象存储/S3 兼容协议按需后补 | 用户需要另一处存储；无异地备份时 Web 持续给出醒目告警。
| **PKI-OPS-D4：恢复密钥** | 采用非对称加密：主控仅存**备份加密公钥**，用户独立、离线保管恢复私钥（可用 age/X25519 体系）；首次设置校验恢复能力并提示丢失无法解密。不要把恢复私钥、弱口令或明文导出文件与备份放在一起 | 对管理员增加一次妥善保管恢复密钥的工作，换取自动备份无需常驻解密密钥。
| **PKI-OPS-D5：迁移体验** | 提供 `fleet-server restore` 类**一次性 CLI 恢复向导**（名称暂定）；在新 VPS 上选择兼容主控版本，导入备份、使用离线恢复密钥、校验 Root 指纹与 Node ID/签发状态，确认旧主控隔离后更新 `agent.example.com` DNS；原证书有效且网络/信任连续时 Agent 自动重连，无须逐台重装 | 需要一次手动恢复，首版不做无人值守自动迁移。
| **PKI-OPS-D6：安全恢复模式** | 恢复后默认进入**隔离/只核对模式**：暂停待执行、审批中、过期/不确定结果任务；逐项核对管理员授权、节点吊销及证书状态。若备份与灾难时间之间存在授权/吊销变更，必须依据可信外部记录补录；无法证明记录完整时，先暂停受影响节点任务并人工复核，**不让旧备份复活已吊销身份** | 恢复后的第一次启用增加人工检查，但能防止权限回滚。
| **PKI-OPS-D7：验证与演练** | 每次生成备份后校验完整性和加密文件清单；默认每季度在**隔离测试环境**完整恢复一次，报告最新恢复点、异常和耗时；不凭设计稿承诺具体 RPO/RTO，先实测 | 季度演练需要管理员花一点时间及测试机资源。
| **PKI-OPS-D8：运行形态** | 继续使用 Go + SQLite 单主控架构；备份和恢复由主控内置功能/一次性 CLI 完成，**不新增常驻数据库、KMS、主备集群或 Agent 侧备份守护服务**；AI/插件最多发起待管理员确认的备份/恢复建议，无权导出私钥或解密凭据 | 管理员在重大灾难中仍需手动恢复；适合个人/小团队。

### 批准后的执行边界与注意事项

- **恢复并非绕过安全验证**：迁移应延续既有私有 Root SPKI 指纹、在线 Intermediate、Node ID、吊销/授权状态和 Agent 原域名；不能以“仍叫同一域名”为由信任新主控。
- **备份包与恢复私钥物理分离**：在线主控仅保存加密公钥；恢复私钥不提交 Web/API、Agent 或 AI Tool。离线 Root CA 私钥既不能进入在线备份，也不能通过恢复向导自动生成替代物。
- **加密文件校验不等于恢复成功**：每次备份检查清单与密文完整性、上传结果；季度隔离演练才验证实际解密、SQLite 一致性、证书/授权恢复。不要声称系统在线持有解密私钥来完成自动解密验证。
- **跨文件一致性**：数据库在线快照和凭据/证书/配置版本要通过受控快照窗口、清单与原子封装关联；避免 SQLite 与外部中间 CA 私钥或吊销记录属于不同时间点。
- **异地存储安全**：SFTP 必须验证服务端主机密钥，使用最小权限凭据与固定远端目录，备份失败或落后于恢复要求时报警；本地缓存不是第二份灾备。
- **旧主控疑似被入侵时不能直接切换**：需要人工作证书、签发密钥和控制端身份的事故响应，单纯 DNS 改动和旧数据库恢复不能让旧主控失去有效控制凭据。

## 4. 恢复包细目与排除项

**应恢复**：SQLite 的用户/角色、节点注册与证书映射、授权/吊销清单、服务分组、插件启用与配置、任务历史和执行 ID、审计元数据、PKI 发行序列号/状态、主控端点配置、公共 Root 证书与指纹、Intermediate CA 密钥/证书、必要的加密配置与密钥封装材料、Cloudflare 最小权限 Token/ACME 账户私钥（受同一加密备份保护）、版本/数据库迁移清单。

**不自动包含**：离线 Root CA 私钥；Agent 节点身份私钥、Agent 本地网站 TLS 私钥；第三方服务器系统完整备份、无界 stdout/stderr 历史、明文 API Key 或恢复私钥。大日志可采用有界单独归档策略；缺失旧日志不能妨碍核心恢复，但应在恢复报告中标注。

**一致性**：必须使用 SQLite Online Backup API 或同等一致性方法，**不得只在 WAL 运行时裸 `cp` 数据库主文件冒充完整备份**；清单含 schema_version、created_at、agent_endpoint、root_spki_sha256、snapshot_id、文件校验和、加密格式、发行版本以及变更记录高水位等信息。恢复时验证摘要、加密验证、数据库 `integrity_check`、版本兼容及关键关联记录完整性。

## 5. 标准恢复步骤

1. **排除双主**：确认旧主控已停止、网络隔离或已完成可信的故障隔离；如果旧机可能仍被攻击者控制，不能仅修改 DNS 就认定它失效。先由管理员执行安全事件处置，必要时轮换受影响的在线签发/服务器身份凭据。
2. **准备新 VPS**：安装经可信签名验证的兼容版本 Go 主控；不要启用注册和任务派发，管理界面只绑定本地/SSH 隧道用于恢复。
3. **导入并解密**：离线向恢复向导提供恢复私钥，解密加密恢复包；程序不回显/持久保存该私钥，并核验备份清单和数据库一致性。
4. **核验身份**：检查 `agent.example.com`、Root CA SPKI 指纹、Intermediate CA 与节点证书信任链、Node ID、吊销列表、授权及数据库迁移状态。如在线 Intermediate 私钥缺失但离线 Root 可用，按已批准的 BOOT-001 流程离线签发新 Intermediate 并确保旧有效客户端证书可校验/续签。
5. **核对旧任务与撤销**：所有未完成/状态未知/原先等待派发的任务默认冻结，不能在主控重启后自动补跑；根据独立可信记录补录备份点之后的吊销/权限变化；无法确认时保持受影响节点的执行权限禁用并人工复核。
6. **切换入口**：确认旧主控已安全隔离后修改 DNS（保留原 Agent 连接域名及正确的 TLS 证书），上线新控制端。Agent 根据既有断线重连策略自动重连。确认无冲突、证书有效、Node ID 与授权一致后逐步解除隔离模式。
7. **验证/收尾**：先只读查询和一台测试节点验证；核对 SQLite / API / mTLS、证书轮换、插件和 Cloudflare 连接，手动确认任务恢复；导出灾难恢复报告并重新开启定时备份。

## 6. 失败场景与边界

| 场景 | 正确处理 | 原 Agent 要重新安装吗？ |
|---|---|---|
| 原主控坏掉，异地备份和恢复密钥齐全，原域名及 Root 信任可恢复 | 新 VPS 恢复、DNS 切换、Agent mTLS 重新连接 | 通常不需要 |
| 仅主控公网 IP 更改 | 保持原域名和有效私有证书链，改 DNS | 不需要 |
| Intermediate 私钥丢失，**离线 Root 私钥可用**、节点身份 DB 完整、已有证书仍有效 | 离线签发新的 Intermediate；按信任链与换证规则恢复签发 | 通常不需要 |
| 备份落后于最新节点吊销/权限变更 | 恢复隔离模式，审计重建撤销和授权；不自动派发 | 无需因迁移全部重装，但需人工复核 |
| **离线 Root CA 私钥遗失**但旧 Intermediate 尚有效 | 短期维持现有信任可能可行；必须规划迁移新根，不能长期承诺可恢复 | 取决于旧可信通道和证书有效期 |
| **Root 信任链已无法验证**且无可信恢复路径 | 不得因使用相同域名就无条件信任新主控 | 可能需要可信手动重新注册 |
| 备份文件或恢复私钥失踪 | 无法完成解密/安全恢复，提示实际缺失项 | 可能需要重建部署 |
| **旧主控仍可发出有效命令**或疑似遭入侵 | 禁止双主，隔离旧机并处置签发与控制端密钥 | 视失陷影响而定 |
| Agent 本地身份私钥丢失 / 其证书全部过期 | 依 BOOT-001 做管理员授权的身份恢复/替换 | 需要恢复或重新注册该节点 |

**关键区分**：这是“灾难备份恢复”，**不是主控失陷后的可信性自动恢复**。窃取了在线中间 CA 私钥、旧主控身份密钥或备份解密私钥时，需要额外评估泄露范围与证书撤销/重新签发。单主架构没有可自动消除旧控制端权限的魔法；方案须保守，避免夸大保证。

## 7. 接口与实现边界（设计行为已批准，路径与字段仍为候选）

- `GET /api/v1/backups`：列出元数据，**不返回私钥或备份内容**。
- `POST /api/v1/backups`：管理员确认后手动创建加密备份；仅使用预配公钥；操作需审计。
- `GET /api/v1/backups/{id}/download`：仅管理员下载**密文**备份；短时授权/审计/大小限制。
- `GET /api/v1/recovery/readiness`：检查最近异地备份、Root 指纹和恢复密钥持有**证明（无需上传恢复私钥）**、吊销高水位、兼容版本等；提示问题。
- `fleet-server restore --archive <encrypted-file>`（示例命令）：本地 CLI，停服务状态运行，接收不落盘的密钥输入、校验恢复包、运行只读检查，管理员显式确认后切换数据库；正式参数由后续实现统一。
- `recovery_mode`：状态保存在受保护配置，禁用派发、人工审批/续派、危险工具及新注册；恢复前不可依赖普通 AI 对话自动解除。

**低配 VPS**：备份采用流式加密、输出有界、低 I/O 优先级；磁盘不足/上传失败警报，不缓存无限历史；恢复不启动第二个常驻进程。必须在 1 核 1GB 测试备份峰值内存和 SQLite 在线快照产生的写入影响。

## 8. 验收测试（开发阶段执行）

1. 10/50 个模拟 Agent 的 Node ID 在迁移后保持不变，原域名与 Root CA SPKI 连续，证书有效节点不重新安装即可重新连上。
2. 篡改备份密文、清单或使用错误恢复私钥均拒绝恢复，且不覆盖当前已验证的数据库。
3. 带 WAL 写入压力的 SQLite 在线快照完整可恢复；随机中断时不产生被标记为有效的半成品。
4. 备份中不得出现离线 Root 私钥、Agent 身份私钥或网站 TLS 私钥；无明文 API Key。
5. 刻意恢复早于某次吊销/任务的旧备份，受影响节点不可立即执行，待派发任务不自动补跑；禁止过期任务复活。
6. 中间 CA 丢失但离线 Root 存在时，模拟受控新 Intermediate 签发和旧节点有条件续签；根私钥丢失时拒绝伪称已恢复。
7. 旧主控仍活动或旧主控凭据疑似失陷时，恢复流程报警/要求隔离，不能出现两个正常运行的可派发任务主控。
8. 异地备份失败、恢复密钥未妥善保管、备份超过默认间隔时 Web 告警；报告实际恢复耗时和最近有效恢复点。
9. 1 核 1 GB Linux VPS 实测 CPU、峰值 RSS、磁盘占用、恢复耗时；测试前不承诺数值。
