# Server Fleet v0.9.2 · 正式 PKI 入网与 raw 安装修复

**修复 v0.9.1 正式 provisioned 模式的阻断缺陷。** 旧版签发器返回 Leaf → Intermediate → Intermediate，Agent 正确拒绝该链。本版返回 Leaf → Intermediate → 固定 Root，并在签发器构造时拒绝重复、乱序或缺少固定根的链。实际 provisioned loader → HTTPS 入网 → 真实 Agent CLI → 本地身份重载纳入回归。

- 对仍有效的已批准入网/续期重试，仅对确定的旧重复 Intermediate 形态补齐公开根链；保留同一个 leaf、私钥、序列号、指纹、期限和原签发记录。撤销、信任代次与令牌过期校验不变，不自动重新入网或重放任务。
- 新增 `deployment/raw-install.sh`：主控/Agent 共用 raw.githubusercontent.com 入口，版本固定，后续脚本摘要固定。Agent 完整命令由控制台生成，令牌仍在终端隐藏输入。
- 分发引导下载支持已固定的私有 HTTPS CA；不写系统根、不关闭 TLS 校验。
- 新增发行材料在线下载/校验、现有分发升级及经签名公开包引导的新主控安装模式。离线签名步骤保留；不在线生成离线 Root 或发行私钥。
- 原50项数据库迁移/原 SQL、keyring、PKI 和执行账本保持，不新增迁移。先升级 Controller，再按需升级 Agent/签名安装源；仅更新 catalog 不会修复旧主控程序。

升级前备份 DB、原凭据密钥、PKI、配置和账本，运行只读 `controller upgrade-check`。仍有效的旧批准请求可在修复后使用原意图重试；过期令牌不能复活，按 [UPGRADE.md](../../deployment/UPGRADE.md) 显式重新接入/替换。不要清空身份或数据库。

下载 Linux amd64/arm64 核心包并校验随附 SHA256SUMS，build-manifest.json 记录精确源码和工具链。**预编译核心包仍未做离线发行签名**，部署者签名后才能作为可信安装/更新源，不把 SHA256 冒充签名。v0.9.1 的 tag/资产不覆盖；仍含旧 Bug，勿再作为新主控安装源。

raw 入口、各模式和一次信任准备见 [RAW-INSTALL.md](../../deployment/RAW-INSTALL.md)。Xray Runtime/Host、受限 Bearer HTTP、真实供应商/root/双机/物理 ARM/硬1C1G 等既有验收边界保持。
